## 라운드 1 → v2 반영 사항
1. 기술 스파이크 1주를 로드맵 맨 앞에 추가, 통과 기준 명시. 녹음 포맷을 iOS AAC / Android opus로 정정. 곡별 자르기 제거(오프셋 재생).
2. MVP-1을 "호스트 폰 1대 + 녹음 + 마커 + 마커 지점 재생 + 카톡 공유 카드"로 축소. 각 기능에 가설 검증 필요 여부 표기.
3. "손이 없다" 반론 수용: 멈춤 자동 감지(무음 구간)를 마커 후보의 기본 경로로, 손 마커는 보조로. 0단계 참관 관찰 항목·통과 기준 추가.
4. 수익 숫자를 가설·측정 방법·손익분기 계산으로 대체. 보관 무제한 삭제.
5. 단계별 실패 기준·실패 시 행동 열 추가. 8주를 주 단위로 분해, 주당 투입 시간 명시.
6. 문제 정의 수치를 "가설·측정 방법"으로 표기. 동아리 밴드를 1차 타깃에서 제외.
7. 대체재 표 확장 + "왜 하나 더 까는가" 열. 카톡을 유통 채널로 쓰는 공유 카드 설계. Capacitor 비용 명시. 모방 방어 단락.

## 라운드 2 → v3 반영 사항
1. H3 "손으로 자른 30초 클립을 단톡방에 올려 열람 50%·재생 30%"를 0-a 통과 기준으로. 실패 시 MVP-1 착수 안 함.
2. 스파이크에 멤버 기기 재생(카톡 인앱)·강제 종료 복원·앱 전환 복귀·카톡 OG 미리보기 4행 추가. 스택에 Edge Function OG 렌더 추가.
3. 사실 정정: 진동 → 화면 플래시, 배터리 경고 Android 한정, iOS 7일 정책 문장 수정.
4. 유료 혜택을 과제 축 중심으로 재설계. 부가세·PG 수수료 반영 순매출 4,300원, 손익분기 9팀. 시나리오 3을 5%(1,000+53)로, 환율 1,400원 통일.
5. 0-b를 3주(감지는 사후 분석)로, 1단계를 개발 8주 96시간 + 실사용 겹침 10주로. 4~5주차 병합·업로드 2주. 검증 밴드 "내 밴드 제외 지인 2팀", "리더가 4주 중 4주 켬" 기준 추가. 초과 시 빼는 순서 명시.
6. 반론 추가: 리더 폰 2시간 잠김(예비 폰 권장), 멤버 폰 재생 호환, 폰 영상이 더 낫다.
7. 곡 종료 제외 규칙(다음 곡 버튼 직전 30초), 재생 구간 "멈춤 30초 전~20초 후"(H5로 조정), 페달을 MVP 이후로. 대체재에 "리뷰 안 함"·"폰 영상 촬영" 추가. 2단계 모집 방법·비용, 3단계 획득 경로 추가.

## 라운드 3 → v4 반영 사항
1. 3단계 획득을 "고유 밴드 풀 × 전환율 = 누적"으로 재계산(제휴 12곳 풀 384팀). 목표 200팀 → 120팀, 손익분기 기준 유료 9팀.
2. 손익 결론 문장 수정, 2%·5%·10% × 120·200팀 6개 시나리오. 오디오 저장을 R2(이그레스 무료)로, 호스팅·OG를 Cloudflare Pages(커스텀 도메인 무료)로. 도메인·포스터·Capacitor 비용 행 추가. 누적 가입 기준 저장량. 4,900원 근거를 월 회비 대비로.
3. 곡 종료 분류를 "대화 수준 90초 이상 지속"으로(버튼 타이밍 무관). 임계값 −20dB 수치화. 곡 이름 입력(리뷰, 선택). 카드 표시 문자열 확정.
4. H6(리더가 앱 없이 4주 연속 녹음) 추가, 실패 시 착수 안 함. H3 측정을 멤버별 개별 링크로. 반론 표에 리더 부담·녹음 동의·해체 주기 행 추가.
5. 1단계 시간표에 0-b 재사용 열, 4~5주차 세분화, 30% 버퍼 → 125시간 11주. 0-b 주 6시간 명시. 검증 밴드 3~4팀, "열린 합주의 100%".
6. 멤버 측 화면 흐름(카톡 카드 → 인앱 리뷰 → 재생), 세션 종료 → 카드 발송 시간축(12시간 목표), 아침 푸시, 리더 부담 3단계 표.
7. §7.1에 Android mp4 우선 확인, 청크 독립성·헤더 보존 remux, 링크 도메인, "1분만 잃는다 → 목표·미검증" 반영. 로그인을 MVP에서 제거(기기 토큰). 가설 후반 지표 "다음에 → 맞춰봄 체크 50%" 추가. 내 밴드 실측 표 틀(0-a 1주차 산출물).

## 라운드 4 → v5 반영 사항
1. 활성 = 누적 ÷ 1.5로 통일. 기본 목표 90팀(제휴 12곳 × QR 25%), 확장 180팀은 미달임을 명시. Pro 손익분기 유료 10팀 = 활성 90팀의 11%.
2. 곡 종료 분류: [다음 곡] 버튼 직전 멈춤 우선, 시간 임계값은 버튼 미사용 시만 H5 90퍼센타일. H5를 분포 분리 기준으로. 곡 종료 오탐율 20% 별도 측정. 노들링 미탐 → 대화 대역 에너지 비율 보조 신호.
3. 스파이크를 구축 26시간 / 측정 16시간으로 분리, 7주. R2 presigned URL 발급 Pages Function 추가, TUS 문구 제거. 1단계를 재사용분 제외 74+22 = 96시간 8주 + 온보딩 1주 + 실사용 4주 = 13주.
4. H6을 "0-b 녹음 페이지를 예비 폰에 화면 켠 채 4주"로 재설계. 0-b를 0-a보다 먼저 시작. H4 설문에 예비 폰 보유·주력 폰 잠금 수용 항목.
5. Supabase 0~2단계 Free, 3단계 Pro(백업·무정지). Free/Pro 고정비 병기, 면허세·PG 가입비·R2 무료 10GB 반영. 유료 10팀 미만이면 Free로 내려 무료 도구 유지, 활성 30팀 미만이면 중단.
6. 대체재 표에 클로바노트·유튜브 타임스탬프 행, "리더 전환 비용" 열. §3에 감지율 실패 시 클로바노트와의 차이 → 과제 축 피벗.
7. "맞춰봄" 체크를 세션 종료 화면으로. 아침 리뷰 3분 목표. 카드 상단 리더 픽 3개(2.5분). 80~99% 녹음률 규칙, n=15 결제 판정 규칙, 설문 미회수 대응. 재발 지표(객관 지표) 추가. 합주실 QR 인센티브 표. 첫 재생 3초 프리로드·faststart 규칙.

## 라운드 5 → v6 반영 사항
1. 요약표 손익분기 10팀 정정 → 이후 경제 구조 자체를 변경: Supabase Free + GitHub Actions 일일 pg_dump 백업(7일 정지 회피·백업 확보)으로 고정비 월 2천 원. 리퍼럴 정산 행·가중 순매출 3,700원 반영. "돈이 되는가"를 "왜 22개월을 쓰는가"(§8.4)로 대체.
2. `isTypeSupported('audio/mp4;codecs=mp4a.40.2')`로 정정, 판정을 실제 iPhone 카톡 인앱 재생으로. 리더 픽은 50초 별도 클립(mp4box.js)으로 추출해 moov 문제·iOS 프리로드 제약 회피.
3. 호스트 2기기 절(녹음 예비 폰·공유 주력 폰, 8자리 연결 코드, 최소 사양, Wake Lock 대신 "자동 잠금 안 함" 대체).
4. H0(고통 정량) 추가, H1 9회 정정, H3를 30초 재생 이벤트 페이지 + 리더 게시 + 클로바노트 대조군(B주)으로, H6에 매주 손 카드 회신 추가, 본인 밴드는 집계 제외(지인 4팀 고정), H7(과제 축 수요) 추가.
5. 감지 스파이크: 세션 3회 폰 2대 동시, 세션 1~2 튜닝 / 세션 3 판정, ±3초.
6. 필요 열 Y/1-b 삼분해 빼는 순서와 일치. 리뷰 3분 산식. 카드 발송 규칙(리더 픽만 정리 없이). 버튼 두 개로 통일. 마커 단위 삭제.
7. QR 전환율을 3개월 코호트로 정의, 램프 반영 → 기본 목표 80팀. 활성/누적 1.5는 2단계 잔존율로 대체. 0-b 구축 1~5주차, 3단계 12주 주 단위. 지인 밴드 수 4팀으로 통일. 참신함 감쇠 기준, 지인 편향 통제(모집 팀과 20%p 비교), 기획자 지속성 반론.

## 라운드 6 → v7 반영 사항
