## 1. 지금은 왜 불편한가

직장인 아마추어 밴드는 대개 이렇게 움직인다. 일정은 단톡방 투표, 곡은 유튜브 링크 던지기, 합주 중 "브릿지 앞에서 다시"는 그 자리에서 잊고, 합주 후 폰 녹음 2시간짜리는 아무도 안 듣고(아예 안 찍는 밴드도 많다), 다음 합주에서 지난주 것을 처음부터 다시 맞춘다.

문제는 실력이 아니라 **기억의 유실**이다. 녹음은 있어도 "어디를 들어야 하는지"를 모르니 안 듣고, 그래서 다음엔 안 찍는다. 안 찍는 밴드도 유실은 같다 — H0는 녹음 여부와 무관하게 재고, 그 비율(H2 분모 밖)은 설문에서 별도 보고한다.

### 근거의 현재 상태

**현재 정량 근거는 0이다.** 기획자 본인 밴드 경험에서 나온 인상뿐이다. 근거를 지어내지 않는다. 코드 0으로 당장 할 수 있는 가장 싼 근거는 **리더 5~10명 전화 인터뷰(30분씩)**이고, 0-a 0주차(6시간)에 하며 발췌를 이 절에 붙인다 — **현재 미실시**. 질문지 5문항:

1. 합주를 녹음·촬영하나. 한다면 무엇으로, 안 한다면 왜.
2. 지난 녹음을 몇 분이나 다시 들었나. 다른 멤버는.
3. 지난주에 정한 걸 이번 주에 다시 맞추는 데 몇 분 썼나(직접 추정).
4. 예비 폰·태블릿이 있나, 기종은. 주력 폰을 2시간 녹음기로 두는 걸 받아들이나.
5. 리더 악기는 무엇이고, 합주 중 손이 비는 순간이 있나.

3번 답의 중앙값은 H0 결과 옆에 참고값으로 병기한다(임계값으로 쓰면 정의상 절반이 넘어 순환이 된다). **이 인터뷰와 클로바노트 5개 확인(H3 행), 사장 2명 인터뷰는 실행 전까지 이 절이 빈칸이다. 문서 수정만으로는 이 절이 더 나아지지 않으며, 실행은 문서 밖의 일이다.** 그 뒤 0단계에서 아래 가설을 잰다. 본인 밴드는 편향 때문에 **모든 가설의 통과 집계에서 제외**하고 측정 절차 예행연습에만 쓴다.

**측정 규칙** (참관자 1명 = 기획자 = 가설 당사자이므로, 규칙 고정만으로는 부족하다)

### 측정 전 가설 (0단계, §9)

**지인 밴드 4팀 + 예비 1팀**(참관·실험, 이후 단계에서도 같은 4팀. **팀당 리더 제외 멤버 2명 이상(3인 밴드도 타깃이므로. 팀별 기준은 2명 중 2 / 3명 중 2 / 4명 중 3 / 5명 중 3), 리더는 손이 비는 악기(1차 타깃과 동일). 섭외 시작 전 후보 6팀을 목록으로 만들고 조건 충족 4팀이 안 모이면 **조건을 이 순서로 완화**한다: 일요일·평일 합주(→ 토요일 팀은 기획자 합주를 그 주 쉼) → 멤버 2명(→ 1명이면 H3 팀별 기준 1/1) → 예비 폰(→ 대여). 그래도 4팀 미만이면 착수 안 함(무기한 연기 없음).** 약 10주 개입(탤리 2주·참관 1주·제2코더 30분·H3 2주·H6 5주)을 섭외 시 명시하고, 중도 이탈 시 예비 팀으로 대체) + 온라인 설문 30팀. "4팀 중 3팀"은 지인 4팀 기준이다. n=4는 잡음이 크다. 그래서 0단계는 확신이 아니라 "착수 안 함"을 걸러내는 관문이고, 확신은 2단계 모집 11팀에서 같은 지표로 다시 잰다.

A주: 기획자가 그 지점 5개를 50초(멈춤 30초 전~20초 후)로 잘라 카드 페이지로 만들고 **리더가** 단톡방에 올림(제품은 픽 3개다 — 5개는 앞 30초 검증용 20초 카드 2개를 포함하기 위해서이고, 재현 조건은 1단계 리더 픽 3개 카드다). ## 2. 누가, 어떤 순간에

**1차 타깃**: 정기적으로 **합주실을 돈 내고 빌려** 만나는 3~6인 직장인 아마추어 밴드 중, **리더가 손이 비는 악기(기타·베이스·키보드)인 밴드**. 서울 홍대·합정·성수·신촌 합주실 상권. 손 마커가 MVP-1의 유일한 입력이므로, 못 누르는 리더는 1차 타깃이 아니다. **0단계 총 기간 상한 13주**(0-a 0~8주차 9주 + H6 꼬리 4주. 섭외 −2·−1주차 2주는 상한 밖, 달력 15주). 팀 이탈로 0-a를 연장하면 상한 17주, 그 이상은 중단.

**타깃 아님**: **보컬 리더 밴드**(합주 중 손이 안 빈다. 2단계에 "마커 담당 멤버 폰" 최소 버전 또는 블루투스 리모컨 입력을 넣은 뒤 편입. 인터뷰 5번으로 비율을 잰다), 대학 동아리 밴드(무료 동방, 세대교체로 누적이 끊김), 노션·시트로 이미 관리하는 밴드(H4로 비율 확인), 프로 세션·스튜디오 팀·원격 실시간 합주를 원하는 사람(§6).

**1차 타깃 크기(0-a 후 기입)**: 4개 상권 정기 밴드(월 2회 이상 예약, 사장 인터뷰로 정의) ___팀 × 손이 비는 리더 비율(인터뷰 5번) ___ = **풀 ___팀.** 예비 폰 조건은 §9 산식의 p로 따로 곱하므로 여기서 곱하지 않는다(이중 계상 방지). 일요일·평일 합주는 참관 섭외 조건이지 사용 조건이 아니므로 산식에 없다. "합주실당 32팀"의 정의는 §8.2 한 곳에 있다(비율 잠정 100%). **실측 풀이 제휴 후보 12곳 합산 384팀 미만이면 그 값으로 §8.3 전 행을 재계산**한다.

**진짜 사용자는 리더다.** 멤버는 링크를 누를 뿐이고, 매주 폰을 세우고 버튼을 누르고 공유하는 사람은 리더 한 명이다.

| 사용자 | 순간 | 성공의 모습 |
| --- | --- | --- |
| 리더(기타·베이스·키보드). 합주를 멈추는 사람 | 합주 시작 전 | 예비 폰을 팔 길이 보면대에 세우고 [녹음] 하나 |
| 리더 | "브릿지 앞에서 다시" 하는 순간 | 멈춘 김에 [중요] 한 번(팔 길이). 얘기하다 놓쳤으면 [방금 것](−90~−40초 창, 세션 중 몇 번이든) |
| 리더 | 다음 날 아침, 주력 폰 | 알림 → 리더 픽 3개 청취(2.5분) → 카톡 공유 |

## 3. 다른 앱과 뭐가 다른가

"밴드 앱"은 대개 **연주 자체**(원격 잼, DAW, 튜너)나 **일정**(네이버 밴드)을 다룬다. 합주노트는 **합주실 두 시간의 결과물**을 다룬다.

1. **멈춤 지점이 50초 카드로 온다.** 2시간 링크 안의 북마크가 아니라, 멈춤 앞 30초 연주가 포함된 클립 3개가 카톡에 뜬다. **MVP-1 시점에 클로바노트와 다른 것은 이것 하나**이고 H3가 잰다. (카톡으로 링크가 가는 것은 클로바노트도 된다 — 차이가 아니다.)
2. **마커가 자동이 된다**(MVP-2, 조건부). 연주가 멈추면 소리가 준다. §4.2 스파이크 판정과 1단계 사후 정확도를 통과할 때만 넣는다. 그때 차이는 둘이 된다.

**모방 방어**: 없다. 기능은 베낄 수 있고, 합주실 QR 단독 게시 같은 조건은 사장 유인(팀당 월 860원)으로는 성립하지 않으므로 주장하지 않는다. 방어 대신 **조기 중단 조건**으로 답한다. 이력 내보내기는 제공한다(밴드의 녹음·마커를 인질로 잡는 것은 §5 삭제·동의 규칙과 어긋난다). **왜 네이버·클로바가 안 만드는가**: 시장이 작아서다 — 서울 4개 상권 정기 밴드 수(0-a 실측값, 현재 빈칸: ___팀)가 대형 사업자의 우선순위에 오를 크기가 아니라는 것이 유일한 논리이고, 실측 뒤 채운다. **베껴지면 남는 것**: MVP-1 시점에는 없다. 과제 축(3단계)이 있으면 밴드별 "다음에" 이력이 남지만 내보내기를 제공하므로 그것도 이식 비용은 아니다. 즉 베껴지면 진다. **그래서 조기 중단 조건을 수치로 둔다**: 같은 형태의 카드(멈춤 지점 짧은 클립 공유)가 네이버 밴드·클로바노트·카톡에 나오면, 그 뒤 3개월 열람 유지율 70% 미만 또는 신규 가입 월 1팀 미만이면 중단. (그 시점에 12개월 평가를 앞당긴다.) 이 프로젝트는 해자를 전제로 하지 않는다.

| 이벤트 로그 · 열람률 | 녹음 시작·업로드·발송·원시 열람·이름 열람·30초 재생. **열람률 = 이름을 고른 멤버 ÷ (멤버 수 − 1). 원시 열람도 병기.** 관리 링크 열람은 리더로 제외. **이름 탭 게이트 허용치**: 이름 열람 ≥ 원시 열람의 70%, 미만이면 게이트를 재생 뒤로 옮긴다. 카톡 인앱 브라우저에서 동작해야 한다(외부 브라우저 열기 요구 금지) | Y |
| 아침 푸시 | 08:00 관리 링크 홈 화면 앱에 Web Push(iOS 16.4+) | 1-b (없으면 온보딩 안내) |
| 세션 종료 화면 "맞춰봄" | 지난 세션 "다음에" 체크리스트 | 1-b (없으면 리더 인터뷰) |

### 4.2 MVP-2 — 자동 감지 (조건부, 1단계 뒤 4주 + 착수 전 스파이크 13h)
200ms RMS + 대화 대역(300Hz~3kHz) 비율, 세션 내 상대 캘리브레이션, 멈춤 후보 → [중요] 없이도 리더 픽 후보. 곡 종료 분류는 [다음 곡] 버튼 우선, 미사용 시 H5 90퍼센타일. **착수 조건 두 개**: 착수 전 스파이크(스크립트 4h + 튜닝 내 밴드 2세션 + 판정 지인 2팀 참관 기록, 감지율 80%·곡 종료 오탐 20%·그 외 오탐 30%) 통과 **그리고** 1단계 실사용 파일에 그 스크립트를 노트북에서 사후 실행해 리더 픽을 정답으로 한 후보 정확도 4주 합산 80% 이상. 대화 대역 비율의 사전 근거는 스파이크 첫 항목(내 밴드 녹음 1개의 연주/대화 구간 스펙트럼 비교)으로 먼저 본다. 실패면 손 마커로 계속하고 §3 2번 차별점은 접는다.

### 4.3 MVP 이후 · 안 만드는 것
- **과제 축**(유료 이유, §8.1): "다음에" 목록이 다음 세션 시작 화면에 셋리스트로 뜨고, 곡별 한 줄 과제·메모. 2단계에 수동 버전.
- 곡 등록(BPM·키·구조), 소셜 로그인, 멤버 폰 마커, 페달, 영상·믹서 파일 업로드(시간축 정렬), 합주실 페이지·리퍼럴, 메트로놈, 공연 셋리스트 내보내기.
- **안 만드는 것**: 합주실 예약·결제 연동, 개별 트랙 녹음·믹싱·악보 편집, 실시간 원격 합주(§6).

**리더의 주간 부담 4동작**: 폰 세우고 [녹음](30초) · [중요]/[다음 곡]/[종료](선택) · **집에서 예비 폰을 와이파이에 붙이고 페이지를 열어 둠(§7.2 예상 2~3분, 상한 10분. iOS는 백그라운드 업로드가 없다)** · 아침에 리더 픽 3개 청취 후 공유(2.5분). 이 4동작 + 예비 폰 조건이 H6(5주)와 1단계(4주)에서 유지되는지가 기준이다.

**시간축**: 21:00 종료 → 22:30 귀가, 예비 폰 와이파이 연결 + 페이지 열어 둠 → 22:35 업로드 완료(통과 기준 3.7분), 카드 생성 → 08:00 푸시 → 공유. 72시간 창의 앞 11시간. 리더가 페이지를 안 열면 카드는 없다 — H6 로그의 "업로드 완료 시각"이 이 동작의 실측이다.

**기기**: 녹음은 예비 폰(iOS 15+ — §7.2 매트릭스의 최저 기기가 iOS 15이므로 그 아래는 지원한다고 적지 않는다. iPhone 6s 이상). **녹음 페이지는 홈 화면 앱으로 설치**(7일 저장소 삭제 예외. 마이크 권한 재요청 여부는 §7.2에서 확인)하고 **서비스 워커가 사전 캐시**해 지하에서 오프라인으로 열린다. 화면 켜둠은 Wake Lock(iOS 16.4+)이 안 되면 "자동 잠금 안 함 + 저전력 해제(저전력이면 30초 강제)". MDM 폰 제외 안내. **충전기 연결 + 밝기 50%**(구형 폰 2시간 발열). Android 녹음 파일이 iPhone에서 안 틀리면 **녹음 폰은 iPhone으로 제한**(§7.2) — 그 경우 Android 리더는 1차 타깃에서 빠지므로 그 비율을 인터뷰 4번(기종)으로 재고 §2 타깃 크기에서 뺀다. 리뷰·공유는 주력 폰에서 관리 링크.

**폰 위치**: **리더 팔 길이, 서서 손 닿는 높이(허리~가슴)로 고정**(손 마커의 전제. 마이크 음질 스파이크도 이 위치 기준). 보면대가 있으면 보면대, **없으면 마이크 스탠드 클립 홀더(5천 원, 온보딩 준비물) 또는 기타 스탠드 위** — 앰프 위(진동)·바닥(발소리·앰프 근접)·주머니·벽 선반(못 누른다) 금지. 보컬 리더 규칙은 2단계에서.

**피드백**: 소리·진동 없음(iOS 진동 API 없음, 거치대 진동은 녹음에 탄다). [중요] 시 **화면 상단 절반 색 반전 1초 + 마커 수 40px** — 보이는 거리 ___m(§7.2 3주차 실측). 배터리 경고는 Android만.

**카톡 카드 실물**: OG 제목 ≤ 20자 — 형식 `{밴드} {M/D} 합주 · 픽 {n}`, 밴드 이름은 6자 초과 시 "…"로 절단(날짜·픽 수 우선). 설명 ≤ 40자(`곡 3개 · 리더 픽 3 · 50초씩`, 멈춤 횟수는 넣지 않는다. 카톡은 2줄에서 자른다), 썸네일 = 정적 이미지 1장(1200×630, 앱 로고). 밴드 이름·날짜는 og:title에만. 리더 고정 문구 아래에 카드가 붙는다.

**타임스탬프 페이지(소스 분리 경로)**: 주머니 속 주력 폰이 아니라 **팔 길이 보면대의 아무 폰**(예비 폰이어도 되고, 화면 켜둘 필요 없음)에서 [시작]·[중요]·[방금 것]·[종료] 네 버튼 72px. 잠금 해제 없이 누르려면 홈 화면 앱 + 자동 잠금 안 함이 필요하므로, 그게 안 되면 예비 폰 경로와 부담 차이가 줄어든다 — H6-b 소요 시간 로그에 "잠금 해제 횟수"를 넣는다.

**동의**: **녹음 시작 전 리더가 단톡방에 고정 문구("오늘 합주 녹음합니다. 멤버만 보는 카드로 공유돼요")를 올린다.** 앱은 게시 여부를 알 수 없다. 문구 복사는 **주력 폰의 관리 링크 홈 [문구 복사] 버튼**(카톡이 있는 폰)에서 하고, 녹음 폰 [녹음] 탭 시 **"단톡방에 올렸음" 체크(자가 신고)를 녹음 시작 조건**으로 둔다 — 게이트는 이 한 곳이다(예비 폰 클립보드는 주력 폰 카톡에 못 붙이므로 복사와 체크의 기기를 나눈다). 실제 미게시율은 1단계 리더 인터뷰로 잰다(§10)(카드를 안 여는 멤버·합주실 직원 등 제3자 음성의 사전 고지). 카드 하단 "이 녹음은 ○○밴드 멤버만 보라고 리더가 공유했습니다. 만료 ○월 ○일. 삭제 요청은 리더 또는 [기획자 연락처]". 리더는 마커·세션 단위 삭제.

## 6. 왜 실시간 원격 합주를 하지 않는가
연주자가 어긋남을 못 느끼는 왕복 지연 상한은 20~30ms. 같은 도시 유선에서도 아슬아슬하고 모바일·와이파이는 불가능하다(Jamulus·JamKazam이 10년째 "유선 + 인터페이스 + 같은 지역"이 전제). 타깃 밴드는 이미 매주 만난다. 1인 개발로 실시간 오디오를 하면 다른 모든 것이 밀린다.

| 항목 | 선택 | 이유 · 제약 |
| --- | --- | --- |
| 앱 | PWA (React + Vite + TS) | 스토어 없음. 멤버는 링크만 |
| 호스팅 · 링크 도메인 · OG | Cloudflare Pages(무료, 커스텀 도메인 무료) + Pages Function이 `/s/:token`에 링크별 OG HTML 응답. **썸네일은 서버에서 그리지 않는다** — 무료 플랜 CPU 한도 호출당 10ms에 Satori+resvg 한글 렌더는 안 들어가고 한글 폰트 번들도 스크립트 3MB(압축) 한도와 충돌한다. 정적 이미지 1장(앱 로고) + og:title에 밴드 이름·날짜 | 카톡 스크래퍼는 서버 HTML의 OG만 읽는다. ### 7.2 기술 스파이크 (0-b, 9주 · 주 6시간 = 54시간) — 통과 못 하면 MVP 시작 안 함

실제 합주실, 실제 합주 중. **구축 22 · 측정 17.5 · 예비 14.5(27%) = 54** 분리. 감지 스크립트·튜닝·판정(구축 4 + 측정 9)은 MVP-2 착수 전 4주로 이관. 구축물은 1단계에서 재사용. 1주차 녹음 페이지 = H6·H3 A·B주 도구, 2주차 카드 페이지 = H3 도구이므로 **0-b가 0-a보다 1주 먼저** 시작한다.
