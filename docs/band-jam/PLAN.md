# 합주노트 — 합주실에서 "여기 다시"를 잃어버리지 않는 앱

> 기획안 v8 · 모바일 웹(PWA) · 호스트 폰 1대로 시작 · 코드 전에 손으로 수요 검증

## 1. 지금은 왜 불편한가

직장인 아마추어 밴드는 대개 이렇게 움직인다.

- **일정**: 단톡방에서 "이번 주 토 7시 ㅇㅇ합주실?" → 투표 → 누군가 예약
- **곡 선정**: 단톡방에 유튜브 링크 던지기 → 합주실 가서 결정
- **합주 중**: "브릿지 앞에서 다시" → 몇 번 맞추고 넘어감 → 그 자리에서 잊음
- **합주 후**: 폰 녹음·영상 2시간짜리를 단톡방에 올림 → 아무도 안 봄. 아예 안 찍는 밴드도 많다
- **다음 합주**: 지난주 얘기했던 걸 다시 처음부터 맞춤

문제는 실력이 아니라 **기억의 유실**이다. 녹음은 있어도 "어디를 들어야 하는지"를 모르니 안 듣고, 그래서 다음엔 안 찍는다.

### 근거의 현재 상태

솔직히 적는다. **현재 정량 근거는 0이다.** 기획자 본인 밴드 경험에서 나온 인상뿐이다. 이 문서는 근거를 지어내지 않고, 0-a 첫 주에 아래 표부터 채운다. 표가 채워지기 전까지 이 기획안의 문제 정의는 가설이다. 본인 밴드는 편향 때문에 **모든 가설의 통과 집계에서 제외**하고, 측정 절차 예행연습에만 쓴다.

### 측정 전 가설 (0단계에서 확인, §9)

**지인 밴드 4팀**(참관·실험, 이후 단계에서도 같은 4팀) + 온라인 설문 30팀으로 잰다. 통과 기준의 "4팀 중 3팀"은 지인 4팀 기준이다. n=4는 잡음이 크다는 것을 안다. 그래서 0단계는 "확신"이 아니라 "착수 안 함"을 걸러내는 관문이고, 확신은 2단계 모집 11팀에서 같은 지표로 다시 잰다.

### 대체재 — 사람들은 지금 무엇으로 버티는가

새 앱은 "갈아타는" 것이 아니라 **하나 더 까는** 것이다. 멤버에게는 "왜 하나 더 여는가", 리더에게는 "지금 하던 것보다 얼마나 더 무거운가"에 답해야 한다. 가장 큰 경쟁자는 앱이 아니라 **"리뷰를 아예 안 하는 관성"**이다. H3·H6이 이 관성을 재고, H3의 B주가 가장 가까운 대체재(클로바노트)와 직접 비교한다.

| 대체재 | 지금 맡는 것 | 못 하는 것 | 멤버: 왜 하나 더 여는가 | 리더: 전환 비용 |
| --- | --- | --- | --- | --- |
| 리뷰 안 함 | 아무것도. 비용 0 | 다음 합주가 지난주 반복 | 카드 한 번 → 리더 픽 3개 = 2.5분. 그래도 안 열면 H3 실패 | 0 → 주 3동작(§5.1). 이 차이를 H6이 잰다 |
| 단톡방에 "브릿지 다시" 한 줄 적기 | 기억 보조, 비용 거의 0 | 소리가 없다. 스크롤에 묻힘 | 한 줄 메모는 앱 안에서도 되고("다음에"), 거기에 소리가 붙는다 | 한 줄 적기 vs 폰 세우기. 후자가 무겁다 |

## 2. 누가, 어떤 순간에

**1차 타깃**: 정기적으로 **합주실을 돈 내고 빌려** 만나는 3~6인 직장인 아마추어 밴드. 서울 홍대·합정·성수·신촌 합주실 상권 중심.

**타깃 아님** (지금은):
- **대학 동아리 밴드** — 무료 동방에서 합주하므로 "시간이 돈"이라는 압력이 약하고, 세대교체로 밴드 단위 누적이 끊긴다. 2단계 이후 별도 검토.
- **노션·시트로 이미 관리하는 밴드** — 이미 도구가 있고 갈아탈 이유가 약하다. H4로 비율을 잰다.
- 프로 세션, 스튜디오 녹음 팀, 원격 실시간 합주를 원하는 사람(§6).

**진짜 사용자는 리더다.** 멤버는 링크를 누를 뿐이고, 매주 폰을 세우고 버튼을 누르고 공유하는 사람은 리더 한 명이다. 리더의 주간 부담은 §5에서 3동작으로 압축하고, H6으로 코드 전에 **앱과 같은 조건에서, 매주 결과를 돌려주면서** 잰다.

| 사용자 | 순간 | 성공의 모습 |
| --- | --- | --- |
| 리더(보통 기타·보컬). 합주를 멈추는 사람 | 합주 시작 전 | 녹음용 예비 폰을 보면대에 세우고 녹음 시작 버튼 하나 |

## 3. 다른 앱과 뭐가 다른가

"밴드 앱"으로 묶이는 것들은 대개 **연주 자체**(원격 잼, DAW, 튜너)나 **일정**(네이버 밴드)을 다룬다. 합주노트는 **합주실이라는 두 시간의 결과물**을 다룬다.

1. **마커가 자동이고, 멈춤 앞을 준다.** 연주가 멈추면 소리가 준다. 그 지점이 마커 후보다. 클로바노트의 발화 분절도 멈춤 "뒤"의 대화는 자동으로 잡는다. 차이는 **멈춤 앞 30초 연주 구간**을 함께 주는 것 하나이고, 그 하나가 열람률을 바꾸는지가 H3다.
2. **결과가 카톡으로 간다.** 멤버는 앱을 깔지 않는다. 카드 하나, 링크 하나, 구간 재생. 카톡은 경쟁자가 아니라 유통 채널이다.
3. **합주 전·중·후가 이어진다.** "다음에" 마커가 다음 세션 종료 화면에 체크리스트로 뜬다(MVP-1). 과제·셋리스트로 확장(MVP 이후).

핵심 가설은 사실 두 개다. 전반 "녹음을 실제로 듣는다"(H3 → 1단계 열람·재생)와 후반 "다음 합주가 달라진다". **MVP-1은 전반만 Y로 만든다.** 후반 도구(종료 화면 "맞춰봄" 체크)는 1-b이고, 없으면 1단계 실사용 중 리더 인터뷰("지난주 다음에 중 맞춰본 것")로 대체한다. 재발 지표(객관 지표)는 MVP-2다. 전반이 실패하면 과제 축 피벗 여부만 보고, 후반만 실패하면 "듣는 도구"로 유지하고 과제 축 설계를 다시 한다.

**감지율이 실패하면 무엇이 남는가.** 손 마커 + 공유 링크만 남으면 클로바노트와의 차이는 "곡 단위 집계·멈춤 앞 30초·다음 합주 연결" 세 가지뿐이고, 그 셋은 얇다. 그 경우 이 앱은 과제 축 없이는 존재 이유가 없으므로, §7.2 감지율 실패 분기는 "손 마커로 계속"이 아니라 **"과제 축 중심으로 피벗하고 녹음은 부속으로"**이며, 그 피벗이 성립하려면 H7이 통과돼 있어야 한다.

**모방 방어**: 기능 자체는 베낄 수 있다. 남는 것은 밴드별로 쌓이는 세션·마커·과제 이력이고, 유료 플랜의 핵심이 그 이력(§8)이다. 한계도 분명하다. 이력은 밴드가 해체되면 사라지고(§10), 네이버 밴드 같은 큰 플랫폼이 녹음 마커를 붙이면 유통 채널 우위는 그쪽이 갖는다. 초기 1~2년은 "합주실 씬에서 먼저 익숙한 이름"이 되는 속도 싸움이고, 합주실 제휴(§9)가 방어선이다. 그래도 지면 진다. 이 프로젝트는 방어 가능한 해자를 전제로 하지 않는다.

| 곡 등록(BPM·키·구조·코드 차트·참고 링크), 곡 상태, 셋리스트 | 셋리스트 축 |
| 소셜 로그인, 멤버 로그인·파트 태그, 멤버 폰에서 마커 | 호스트 1대로 충분하면 영영 안 만든다 |
| 블루투스 페이지터너 페달로 손 마커 | 니치 장비 |

## 5. 화면 흐름 (MVP-1)

### 5.1 호스트(리더) — 녹음 폰 1대 + 관리 링크

녹음은 **예비 폰** 1대가 한다(녹음 중 다른 앱으로 전환하면 iOS는 마이크 캡처가 끊기므로 주력 폰은 권장하지 않는다). 리뷰·공유는 **관리 링크**를 연 아무 폰에서 한다. 구형 예비 폰에 카톡이 없어도, 주력 폰에서 관리 링크를 열면 된다. 기기 연결·코드는 없다.

| 역할 | 어디서 | 최소 사양 |
| --- | --- | --- |
| 녹음 · [중요] · [다음 곡] · [종료] · 클립 추출·업로드 | 녹음 폰(예비), 관리 링크를 홈 화면에 추가 | iOS 14.5+ (MediaRecorder 기본 활성). **화면 켜둠은 Wake Lock(iOS 16.4+)이 안 되면 온보딩에서 "자동 잠금: 안 함" + 저전력 모드 해제**(저전력이면 30초로 강제됨) → iPhone 6s 이상 가능. 회사 관리(MDM) 폰은 설정이 막힐 수 있어 제외 안내. 구형 폰은 2시간 발열로 밝기가 자동 저하될 수 있으므로 화면 밝기 최소 권장. Android는 Chrome 최신 |
| 아침 알림 → 리뷰(정리·곡 이름) → [카톡 공유] | 주력 폰에서 같은 관리 링크 | 카톡 설치. 푸시는 홈 화면 추가 시 |

```
[녹음 폰 · 녹음 ★]   ● 녹음 중 12:34 · 곡 2 · 마커 7
                     ┌──────────────────────────┐
                     │  (정보: 시간·곡·마커 수)   │
                     ├──────────────────────────┤ ← 아래 1/3
                     │   [ 중요 ]   [ 다음 곡 ]   │   버튼 높이 72px, 두 버튼
                     └──────────────────────────┘
[녹음 폰 · 종료 화면]  (1-b) 지난주 다음에 (3)  ☑ 맞춰봄 ☐ ☐   → [완료]
[관리 링크 · 세션 리뷰]  리더 픽 · 곡별 마커 · 곡 이름(선택) · ▶ · 다음에/삭제 · [카톡 공유]
```

**리더의 주간 부담을 3동작으로 압축한다.** 대체재("리뷰 안 함")의 부담은 0이고, 음성메모는 주머니 속에서 돈다. 이 3동작 + 예비 폰 조건이 4주 이상 유지되는지가 H6과 1단계 통과 기준이다.

| 동작 | 리더가 하는 것 | 목표 시간 | 앱이 하는 것 |
| --- | --- | --- | --- |
| 1. 합주 시작 | 예비 폰 세우고 [녹음] | 30초 | 캘리브레이션, 화면 켜둠, 청크 저장 |
| 2. 합주 중·종료 | 곡 넘어갈 때 [다음 곡] (안 눌러도 됨 — 안 누르면 곡 경계가 시간 규칙에만 의존해 "구간 N"으로 표시됨) · [종료] | 30초 | 멈춤 감지, 곡 종료 분류 |
| 3. 다음 날 아침 (주력 폰, 관리 링크) | 알림 → 카드 훑고 오탐 삭제(선택) → [카톡 공유] | **3분** | (녹음 폰) [종료] 직후 클립 추출 → 와이파이 자동 업로드(클립 먼저, 60초 파일들 다음) → 서버 카드 생성 → 08:00 알림 |

**세션 종료 → 카드 발송 시간축** (목표: 종료 후 **12시간 내** 발송, 1단계 지표)

```
21:00 합주 종료 ─ [종료] 직후 녹음 폰이 리더 픽 클립(3 × 400KB) 추출. 지하, 통신 없음
21:30 지상·와이파이 → 녹음 폰이 클립 먼저, 60초 파일들 다음으로 자동 업로드(R2 멀티파트, 재개 가능)
21:35 클립 업로드 완료 → 서버가 카드 생성 → 관리 링크에 표시 (리더 픽만 노출된 상태로 발송 가능)
22:00 60초 파일 전부 업로드 완료 → 곡별 마커 재생 가능
08:00 다음 날 푸시 "카드 준비됨" → 리더가 주력 폰에서 3분 훑고 공유  ← 72시간 창의 앞 11시간 사용
```

현장 규칙:
- **폰 위치**: 보면대 또는 드럼 반대편 벽쪽 선반. 보컬 마이크 스탠드는 피한다(대화 음량이 연주 음량에 근접해 감지가 흔들린다). 주머니는 녹음이 안 되고 앰프 위는 진동이 탄다.
- 360px 폭, 세로 고정, 다크. 글자 최소 18px, 주 버튼 높이 72px, 두 버튼만.
- **소리·진동 없음**. 피드백은 화면 플래시(테두리 색 0.3초). iOS Safari에는 진동 API가 없고, 거치대 위 진동은 녹음에 탄다.
- 배터리 경고는 Android(Battery Status API)만. iOS는 온보딩에서 "충전기 연결" 안내.
- 통신은 녹음 중 필요 없다. 업로드는 세션 종료 후, 와이파이 잡히면 자동.

### 5.2 멤버 (카톡 → 인앱 브라우저, 로그인 없음)

```
[카톡 카드]  OG: "성현밴드 9/6 합주 · 곡 3개 · 리더 픽 3 · 다시 12"  ← 누르면
   ↓
[리뷰 (읽기)]  리더 픽 (3)                       ← 최소 듣기 = 3 × 50초 = 2.5분
                 ▶ 곡 2 「곡 이름」 12:34  50초
                 ▶ …
               곡 1 · 다시 4  (접힘, 리더가 정리한 뒤에만 펼침)
   ↓ 하나 누르면
[재생]  진행 바(0~50초) · 곡·마커 번호 · [다음 마커 ▶]  · 자동으로 다음 마커로 넘어감(제스처로 시작한 audio 요소 하나를 재사용해 src만 교체 — iOS 자동재생 제한 회피)
```

- **첫 재생 3초 이내**(LTE)의 수단: 녹음은 **60초 단위 독립 파일 120개**로 저장·업로드한다(§7.1, iOS·Android 공통). 마커는 (파일 번호, 파일 내 오프셋)이다. **리더 픽 구간은 녹음 폰이 [종료] 직후 해당 60초 파일 1~2개에서 50초를 잘라 별도 mp4로 추출**(재인코딩 없음, 약 400KB)해 먼저 올린다. 접힌 곡별 마커는 해당 60초 파일(약 480KB)을 통째로 받아 오프셋으로 이동하고, 다음 파일을 이어 재생한다. 2시간 파일 하나의 moov(약 1.5~2MB)를 먼저 받을 일도, Range 요청도 없다. iOS는 사용자 제스처 전 미디어 preload를 무시하므로 프리로드는 하지 않고 파일을 작게 만든다.
- 카톡 인앱 브라우저에서 동작해야 한다(외부 브라우저 열기 요구 금지).
- 멤버 화면에는 쓰기 없음.
- 녹음 동의: 카드 첫 화면 하단에 "이 녹음은 ○○밴드 멤버만 보라고 리더가 공유했습니다. 링크 만료 ○월 ○일. 삭제 요청은 리더에게". 리더는 마커 단위·세션 단위 삭제 가능.

## 6. 왜 실시간 원격 합주를 하지 않는가

- **물리 한계**: 연주자가 어긋남을 못 느끼는 왕복 지연 상한은 대략 20~30ms. 같은 도시 유선에서도 아슬아슬하고, 모바일·와이파이에선 불가능하다. Jamulus·JamKazam이 10년 넘게 매달렸고 여전히 "유선 + 오디오 인터페이스 + 같은 지역"이 전제다.
- **타깃 불일치**: 타깃 밴드는 이미 매주 만난다. 병목은 "함께 연주할 수단"이 아니라 "만났을 때의 결과물"이다.
- **범위**: 1인 개발로 실시간 오디오 네트워킹을 하면 다른 모든 것이 밀린다.

## 7. 기술

### 7.1 스택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 앱 형태 | PWA (React + Vite + TypeScript) | 스토어 심사 없이 배포. 홈 화면 추가. 기존 스택 재사용. 멤버는 링크만 열면 된다 |
| 호스팅 · 공유 링크 도메인 | Cloudflare Pages (무료, 커스텀 도메인 무료) | Supabase Edge Function 기본 URL은 `*.supabase.co/functions/v1/...`이라 공유 링크로 쓰기 어렵고 커스텀 도메인은 월 10달러. Pages Functions가 같은 도메인에서 OG를 렌더한다 |
| **공유 카드 OG 렌더** | Pages Function이 `/s/:token` 요청에 링크별 OG 메타를 넣은 HTML을 응답 → 이후 SPA 로드 | 카톡 스크래퍼는 서버가 준 HTML의 OG만 읽는다 |
| DB · 푸시 | Supabase **Free** (Postgres · Edge Functions for 푸시 발송) | Free 한도(DB 500MB, Edge Function 50만 호출/월, MAU 5만)는 200팀 규모에서도 안 걸린다. Free의 두 문제와 대응: **7일 무활동 일시정지** → 비활동 판정 기준을 0-b 1주차에 확인하고, GitHub Actions 일일 cron에 **REST 헬스 핑 1회 + `pg_dump`(세션 풀러 IPv4 경유 — 러너는 IPv6가 없다)** 를 함께 넣는다. **백업 없음** → 그 `pg_dump`를 비공개 저장소에 보관(무료). Pro(월 25달러)는 유료 밴드가 20팀을 넘어 PITR이 필요해질 때 |
| **오디오 저장** | Cloudflare R2 (월 10GB 무료, 이후 GB당 0.015달러, **이그레스 무료**) | 재생 트래픽이 비용에 안 잡힌다 |
| **업로드 경로** | 녹음 폰 → Pages Function이 R2 멀티파트 **presigned URL** 발급 → 파트(5MB 이상) 직접 업로드, 재개 가능 | R2는 TUS를 지원하지 않는다. 브라우저에서 R2에 직접 쓰려면 서명 발급 계층이 필요하다 |
| 녹음 | MediaRecorder(iOS 14.5+ 기본 활성). **iOS Safari: audio/mp4 (AAC)**. **Android Chrome: `isTypeSupported('audio/mp4;codecs=mp4a.40.2')`로 AAC를 명시해 확인** — Chrome 126+의 mp4 먹서는 Opus-in-MP4도 받으므로 codecs 없이 물으면 iPhone에서 안 트는 파일이 나올 수 있다. AAC 안 되면 webm/opus. 모노 64kbps | AAC로 통일되면 재인코딩 분기가 사라진다. 통일 여부는 스파이크에서 **실제 iPhone 재생**으로 판정 |
| 마이크 제약 | `echoCancellation: false`, `autoGainControl: false`, `noiseSuppression: false` | 기본값은 통화용. 드럼·앰프를 뭉갠다. **iOS Safari는 이 제약을 무시해 온 이력이 있다** → 스파이크에서 확인하고, AGC를 못 끄면 절대 −20dB 대신 **세션 내 상대 캘리브레이션 + 대화 대역 비율을 Y로 승격**(§7.2 실패 분기). 옆방 소리·에어컨 같은 정상 소음도 같은 상대 기준으로 흡수 |
| 로컬 저장 · **60초 독립 파일** | timeslice 청크를 병합하지 않는다. **60초마다 MediaRecorder stop()/start()로 독립 파일**을 만들어 IndexedDB(idb-keyval)에 즉시 저장(경계 손실 ≤0.2초는 스파이크에서 실측). 브라우저가 죽어도 마지막 60초만 잃고, 파일마다 완결된 헤더가 있어 복원·시킹 문제가 없다. 서버에도 120개 파일 그대로 저장, 병합 없음 | webm(첫 청크에만 EBML 헤더)·iOS mp4(moov가 stop()에만 쓰임) 양쪽의 청크 복원 문제를 우회한다. 대가는 파일 수와 경계 손실 |
| 클립 추출 | 리더 픽 50초는 해당 60초 파일에서 **mp4box.js로 파싱 후 init + 미디어 세그먼트를 직접 조립**(내장 기능이 아니라 직접 구현, 8시간). webm이면 EBML 재작성 | "첫 재생 3초"의 전제 |
| 멤버 재생 호환 | Android webm/opus를 iPhone 멤버가 못 틀 수 있다 → 스파이크에서 판정. AAC로 통일되면 문제 소멸. 아니면 **녹음 폰에서 업로드 전 AAC 재인코딩**(WebCodecs, Android Chrome) 또는 호스트 iOS 제한 | 가설 지표(재생률)를 결정하는 것은 멤버 폰이다 |
| 멈춤 감지 | 녹음과 병렬로 AnalyserNode RMS(+대화 대역 비율)를 200ms마다 샘플링, 클라이언트에서 저장. 서버 오디오 처리 없음 | 서버는 파일과 숫자만 받는다 |
| 이력 보존 | 사파리 탭으로 쓰면 "사파리 사용 7일 무상호작용" 시 로컬 저장소가 지워질 수 있다(홈 화면 추가 시 예외). 세션 종료 시 업로드를 끝내는 것이 원칙 | 로컬은 임시 |
| 멤버 식별 쿠키 | Pages Function이 **HTTP Set-Cookie**로 1년 쿠키 발급(document.cookie는 ITP가 7일로 자름). 카톡 인앱 브라우저 유지 여부는 스파이크 항목 | 열람률 분자의 전제. 안 되면 매번 이름 탭 |
| 푸시 | Web Push, 관리 링크를 홈 화면에 추가한 폰. iOS는 16.4+만 | 미지원이면 "다음 날 아침 카드 확인" 온보딩 안내로 대체 |

### 7.2 기술 스파이크 (0-b, 10주 · 주 6시간 = 60시간) — 통과 못 하면 MVP 시작 안 함

실제 합주실에서, 실제 밴드 합주 중에 돌린다. **구축과 측정을 분리**하고, **감지 임계값의 튜닝 세션과 판정 세션을 분리**한다. 구축한 것은 1단계에서 재사용하며, 재사용분은 §9 1단계 시간표에서 뺀다. 0-b 1주차 산출물(녹음 페이지)이 H6 도구, 2주차 산출물(클립 페이지)이 H3 도구가 되므로 **0-b가 0-a보다 1주 먼저 시작**한다.

- Android → iPhone 재생 실패 → 녹음 폰에서 AAC 재인코딩 추가(1단계 +1주) 또는 호스트 iOS 제한.
- 감지율 실패 → **과제 축 중심으로 피벗**(§3). H7이 통과돼 있을 때만. 아니면 중단.

### 7.3 Capacitor 대안의 비용
iOS PWA 녹음이 스파이크를 통과 못 하고 믹서·영상 업로드로도 안 되면 Capacitor 네이티브 래퍼가 마지막 대안이다. 비용: 애플 개발자 계정 연 99달러(≈14만 원), 심사 1~2주, 업데이트마다 심사, "스토어 심사 없이 배포"라는 PWA 선택 이유가 사라짐. 호스트(리더)만 설치하면 되므로 감당 가능하지만 로드맵에 3주를 추가한다. **앱 내 구독은 애플 IAP 수수료 15~30% 대상이 되고 외부 결제 링크는 막히므로**, 이 경로에선 순매출이 4,300원에서 약 3,000~3,700원으로 떨어진다(§8.3 비용 표).

## 8. 수익과 비용

### 8.1 누가 왜 내는가
밴드 단위 결제. 리더 한 명이 결제하고 멤버 전원이 혜택. 합주실비를 이미 회비로 걷고 있어 개인 결제보다 저항이 적다는 것이 가설이다.

유료 혜택은 가치 명제와 맞춰야 한다. 가치는 "세션 후 72시간 안에 듣는 것"에 있고, 오래된 녹음은 아무도 안 듣는다. 그래서 유료 이유는 보관이 아니라 **이력이 다음 합주로 이어지는 것**(과제 축)이다. 오디오 1년 보관은 공연 준비 추이용 부가 혜택이지 이유가 아니다.

| 플랜 | 내용 |
| --- | --- |
| 무료 | 밴드 1개, 최근 4세션 리뷰·오디오(5번째 세션부터 오래된 오디오 삭제, 마커·"다음에"는 남음), 공유 카드 30일 후 만료 |
| 밴드 프로 (월 4,900원, 부가세 포함, 가설) | **과제 축**("다음에" → 다음 셋리스트, 곡별 과제, 메모), 카드 만료 없음, 믹서·영상 파일 업로드, 밴드 2개 이상, (부가) 세션 이력·오디오 1년 |

**지불 의향은 기능이 있어야 잰다.** 2단계 베타에 과제 축의 수동 버전을 먼저 넣고, 베타 말에 실제 결제 링크를 연다. n=15에서 1팀 = 6.7%이므로 전환율은 판정 불가. **판정 규칙**: 0팀이면 실패(유료 오픈 보류, 지불 이유 재설계). 1팀 이상이면 "왜 냈는가/안 냈는가" 인터뷰 15건으로 보완 판정. 전환율은 3단계 첫 3개월(활성 50팀 이상 시점)에 잰다. 가격은 H4 설문(2,900/4,900 의향)으로 초기값을 정한다.

- **판단 규칙**: 12개월 시점 활성 30팀 미만이면 중단(도메인만 남기고 정적 아카이브). 기본 시나리오가 r=20%면 33팀, QR 10%면 33팀으로 경계선이다. 그 위면 비용이 거의 0이므로 무료 도구로 계속 둔다. 유료는 있으면 좋고 없어도 서버가 죽지 않는다.

### 8.4 그러면 왜 24개월을 쓰는가

0단계 10주 + 1단계 14주 + 2단계 10주 + 3단계 12주 = 46주 ≈ 11개월, 그 뒤 측정 12개월 ≈ 23~24개월. 주 12시간, 보상은 기본 월 1~2만 원. 이 투입의 이유를 돈 밖에서 적는다.

| 이유 | 확인 방법 |
| --- | --- |
| **내 밴드가 쓴다.** 기획자 본인이 매주 합주하는 리더이고, 이 도구가 없어서 겪는 손실(H0)이 본인 것이다 | 0-a 1주차 실측 표. 본인 밴드에서조차 H0·H6이 안 나오면 이유가 사라진다 |
| **PWA 오디오 파이프라인 포트폴리오.** 모바일 브라우저 2시간 녹음·복원·remux·R2·OG 렌더는 그 자체로 재사용 가능한 기술 자산 | 0-b 산출물이 독립 저장소로 남는다 |
| **중단 지점이 미리 정해져 있다.** 0단계(가설 또는 스파이크) 실패 → 10~13주 손실(H6 꼬리 포함), 이때 쓴 코드는 스파이크와 1단계 셋업뿐. 1단계 실패 → 24주 | 각 단계 실패 기준(§9) |

| 10 | 지인 4팀 온보딩 방문 (팀당 3시간) | — | 12 (신규, 버퍼 아님) |
| 11~14 | 실사용 4주, 지표 수집, 버그 수정(주 6시간) | — | 24 |

108시간을 넘기면 빼는 순서(전부 1-b): 푸시 → 세션 종료 화면 → 캘리브레이션 → 대화 대역 비율(AGC 해제 불가 시 Y로 승격돼 빼지 않음). Android → iPhone 재생 실패로 재인코딩이 필요하면 +1주.

## 10. 리스크와 반론

| 반론 | 판단 | 대응 |
| --- | --- | --- |
| **진짜 사용자는 리더이고, 앱은 음성메모보다 엄격히 더 무겁다** (예비 폰, 화면 켜둠, 앱 전환 금지) | 맞다. 가장 치명적 | 부담을 3동작으로 압축(§5.1). **H6은 앱과 같은 조건(예비 폰·화면 켜둠)으로, 매주 손 카드를 돌려주며 잰다** — 안 켜면 부담 때문인지, 켜면 가치 때문인지 해석되게. 예비 폰 보유·기종은 H4 설문. 없는 리더에겐 구형 폰을 빌려주고 기록. 구형 폰은 "자동 잠금 안 함"으로 Wake Lock 없이 가능 |
| **H6은 지인이라서 켜는 것이다** | 맞다. 지인 4팀은 편향 | 그래서 2단계 모집 11팀에서 같은 지표(열린 주 녹음률)를 다시 재고, 지인 4팀과 모집 11팀의 녹음률 차이가 20%p를 넘으면 지인 결과를 버린다 |
| **낯선 밴드 리더가 예비 폰을 구해 세팅한다는 전제가 3단계 산식에 없었다** | 맞았다 | QR 전환율에 예비 폰 확보 비율 p(기본 60%)를 곱한다. p는 H4·H6·2단계 모집 11팀에서 확정. 50% 미만이면 믹서·영상 업로드를 3단계 첫 4주로 앞당긴다 |
| **QR 25%는 낙관이고, 10% 이하면 중단선이다** | 맞다. 가장 가능성 높은 결말 | §8.3 민감도 표에 5%·10%·25%를 적고, 10% 이하가 가장 가능성 높다고 인정한다. 3개월 시점 측정으로 12개월을 기다리지 않고 판단을 앞당긴다 |
| **H3 대조 실험이 순서·오염·측정 비대칭으로 판정이 안 된다** | 맞았다 | 2팀 A→B, 2팀 B→A. H6 손 카드는 H3 두 주 뒤에 시작. 두 주 모두 리다이렉트 링크로 사람 단위 클릭을 같은 단위로 집계 |
| **저전력 모드·회사 관리 폰에선 "자동 잠금 안 함"이 안 된다. 구형 폰은 2시간 발열로 밝기가 떨어진다** | 맞다 | 온보딩에 저전력 해제·밝기 최소 안내, MDM 폰은 제외 안내. iOS 15 기기를 스파이크 매트릭스에 포함 |
| **수요 가설을 코드 뒤에 검증한다** | 맞았다 | H3: 0-a에서 손으로 자른 클립을 리더가 단톡방에 올려 열람·30초 재생을 사람 단위로 먼저 잰다. 실패하면 MVP-1을 시작하지 않는다 |
| **H3가 통과해도 클로바노트를 이긴다는 증거는 아니다** | 맞았다 | H3 B주: 같은 밴드에서 다음 주 클로바노트 북마크 링크를 대조군으로. A주 열람률이 B주보다 높아야 통과 |
| **합주 중 마커 누를 손이 없다** | 맞다 | 자동 감지가 기본, 손 마커는 보조. 멤버 폰 마커는 뺐다 |
| **감지율 80%가 튜닝 데이터로 나온 과적합 수치다. 판정이 세션 1회 n=1이다** | 맞았다 | 튜닝은 내 밴드, 판정은 튜닝에 안 쓴 지인 2팀 × 각 1세션, 멈춤 합계 20개 이상, 두 세션 모두 80%(§7.2). 참관 기록 ±3초 대조 |
| **곡 종료가 "다시"로 잡힌다** | 구조적 오탐이었다 | [다음 곡] 버튼 직전 멈춤은 곡 종료 확정. 시간 임계값은 버튼 미사용 시만, H5 90퍼센타일. 분포가 안 갈라지면 시간 분류 제거. 곡 종료 오탐율 20% 별도 판정 |
| **노들링 때문에 멈춤을 놓친다** | 있을 것이다 | 대화 대역 비율(1-b). 감지율 80% 기준에 미탐 포함. 놓친 것은 손 마커 |
| **클로바노트의 자동 발화 분절이 이미 멈춤 마커다** | 맞다. 멈춤 "뒤"는 이미 자동이다 | 증분은 멈춤 "앞" 30초 연주 구간 하나뿐이라고 §3에 못 박고, H3 B주 대조군을 발화 분절 타임라인이 보이는 클로바노트 링크로 세운다. 차이가 없으면 착수 안 함 |
| **감지율이 실패하면 클로바노트와 다를 게 없다** | 맞다 | 실패 분기는 과제 축 피벗(§3). **피벗 목적지의 수요는 H7로 미리 잰다.** H7도 실패면 중단 |
| **H6·1단계 실패가 부담 탓인지 앱 탓인지 못 가른다** | 맞았다 | H6 주별 로그 3열(켰는가 / 기술 실패 / 미실행). 기술 원인은 분모에서 빼고 §7.2로. H6은 0-b 1차 끊김 0회 확인 뒤 시작 |
| **열람률에 리더 본인이 섞인다** | 맞았다 | 분자는 카드에서 이름을 고른 멤버, 분모는 멤버 수 − 1. 관리 링크 열람은 리더로 집계 |
| **옆방 소리·에어컨·노들링으로 −20dB까지 안 떨어진다** | 있을 것이다 | 절대값이 아니라 세션 내 상대 캘리브레이션 + 대화 대역 비율. AGC를 못 끄면 이 경로가 Y |
| **곡 이름 없는 "곡 3"은 멤버가 못 읽는다** | 맞다 | 리뷰에서 곡 이름 입력(선택). 리더 픽이 상단이라 곡 이름 없이도 최소 동선은 된다 |
| **"다시 12군데"는 10분이다** | 맞다 | 카드 상단은 리더 픽 3개 = 2.5분. 나머지는 접힘, 정리 후에만 펼침 |
| **멤버는 앱을 안 연다. 리더가 캡처해서 카톡에 올린다** | 맞다 | 카톡 안에서 미리보기(OG), 링크 하나로 로그인 없이 50초 클립 재생. 열람·재생·4주차 감쇠가 1단계 기준 |
| **멤버 폰에서 재생이 안 된다** (Android → iPhone) | 있을 수 있다 | codecs 명시로 AAC 확인 + 실제 iPhone 카톡 인앱 재생으로 판정. 실패 시 녹음 폰 재인코딩 +1주 |
| **2시간 파일 하나는 moov(약 1.5~2MB)부터 받아야 하고, iOS 청크는 헤더가 없어 복원이 안 된다** | 맞았다 | 둘 다 **60초 독립 파일 120개**로 우회. 병합·Range·헤더 청크 보존이 전부 필요 없다. 대가인 경계 손실 ≤0.2초는 스파이크 실측 |
| **리더 픽이 0개면 카드가 비어 나간다** | 맞았다 | 자동 감지 마커 중 멈춤 길이순 상위 3개를 자동 노출 |
| **공개 링크로 멤버 전원의 연주·대화가 재생된다** | 동의·유출·삭제 요청 | 카드에 공유 주체·만료·삭제 요청 안내. 기본 30일 만료, 리더 즉시 만료, **마커 단위·세션 단위 삭제**. 토큰 128비트. 밴드 생성 시 "멤버에게 녹음을 알렸다" 체크 |
| **녹음 파이프라인이 안 돌아간다** | 가장 위험한 기술 가정 | §7.2 스파이크 60시간. 실패 시 믹서·영상 파일 업로드로 소스 변경 |
| **호스트 폰 한 대가 단일 장애점** | 맞다 | 1분 청크 + 헤더 보존 remux를 스파이크로 확인. 2단계에서 밴드 내 누구든 호스트, 믹서 녹음을 대안 소스로 |
| **폰 영상이 더 낫다** | 정보량은 영상이 많다 | 2단계에 영상 파일 업로드. 영상도 폰을 세워야 하므로 리더 부담은 같다 |
| **합주실 사장이 QR을 붙일 이유가 없다** | 맞았다 | 합주실 페이지·리퍼럴 20%·믹서 연동·부담 0(§9). 반응은 0-a 사장 인터뷰로 확인 |
| **아마추어 밴드는 해체·휴식이 잦다** | 맞다 | 무료 플랜도 마커·"다음에"는 남긴다. 유료 이유는 보관이 아니라 과제 축. 2단계 6주 잔존율로 활성/누적 비율을 잡고, 6개월 이상 활동 밴드가 50% 미만이면 월 결제만 |
| **돈이 안 된다** | 맞다. 기본 월 1~2만 원, 확장 3만 원대 | 고정비를 월 2천 원으로 눌러 손익분기 1팀. "잃는가"가 아니라 "왜 22개월을 쓰는가"가 질문이고, 답은 §8.4(내 밴드가 쓴다·기술 자산·중단 지점 확정) |
| **기획자가 24개월을 못 간다** | 가장 흔한 실패 | 중단 지점이 10~13주·24주에 미리 있다. 어느 지점에서든 멈추면 그때까지의 산출물(실측 데이터·스파이크 코드)이 남는다. 주 12시간을 넘기지 않는다 |
| **누적과 활성을 섞었다. 6주 잔존율의 역수는 12개월 비율이 못 된다** | 맞았다 | 월 이탈률 r 기반 Σ(월 가입 × (1−r)^k)로 교체. r=10%·20% 두 줄. 15팀 6주로는 r을 못 가르므로 초기값이고 3단계 3개월에 재기입. 램프·예비 폰 반영 기본 목표 50팀 |
| **네이버 밴드가 같은 걸 붙이면** | 유통 우위는 그쪽 | 초기 1~2년 합주실 씬 인지도 + 합주실 제휴가 방어선. 그래도 지면 진다 |
| **iOS PWA 녹음 제약** | 스파이크에서 판정 | 통과 못 하면 믹서·영상 업로드 → 그것도 안 되면 Capacitor(§7.3) |
| **합주실 통신 불량** | 지하가 많다 | 녹음 중 통신 불필요. 업로드는 사후·자동·재개 가능 |
| **1인 개발 범위 초과** | 늘 그렇다 | 0-b 60시간(예비 10) + MVP-1 108시간(버퍼 46%) + 온보딩 12시간. 넘기면 빼는 순서를 미리 적었다. 3단계 12개월 운영은 주 4시간으로 따로 잡았다 |
