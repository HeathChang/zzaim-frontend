# 합주노트 — 합주실에서 "여기 다시"를 잃어버리지 않는 앱

> 기획안 v3 · 모바일 웹(PWA) · 호스트 폰 1대로 시작 · 코드 전에 손으로 수요 검증

일주일에 한 번, 두 시간짜리 합주실을 빌려 만나는 아마추어 밴드를 위한 앱.
합주 중 연주가 멈춘 지점을 녹음에 자동으로 표시하고, 다음 날 그 구간만 다시 들으며 "다음에 맞출 것"을 남긴다.

| | |
| --- | --- |
| **핵심 가설 하나** | "합주 중 멈춘 지점만 다시 들을 수 있으면, 밴드는 녹음을 실제로 듣고 다음 합주가 달라진다" |
| **코드 전에 손으로 검증** | 참관하며 멈춤 시각을 적고, 30초 클립을 손으로 잘라 단톡방에 올린다. 멤버가 안 열면 앱도 안 만든다 |
| **MVP는 이 가설만 검증한다** | 호스트 폰 1대 · 녹음 · 멈춤 지점 마커 · 그 구간 재생 · 카톡 공유 카드. 그 외는 전부 뒤로 |
| **가장 위험한 것부터 확인한다** | 모바일 브라우저 2시간 녹음과 멤버 폰 재생이 되는지를 스파이크로 먼저 확인 |

---

## 1. 지금은 왜 불편한가

직장인 아마추어 밴드는 대개 이렇게 움직인다.

- **일정**: 단톡방에서 "이번 주 토 7시 ㅇㅇ합주실?" → 투표 → 누군가 예약
- **곡 선정**: 단톡방에 유튜브 링크 던지기 → 합주실 가서 결정
- **합주 중**: "브릿지 앞에서 다시" → 몇 번 맞추고 넘어감 → 그 자리에서 잊음
- **합주 후**: 폰 녹음·영상 2시간짜리를 단톡방에 올림 → 아무도 안 봄. 아예 안 찍는 밴드도 많다
- **다음 합주**: 지난주 얘기했던 걸 다시 처음부터 맞춤

문제는 실력이 아니라 **기억의 유실**이다. 녹음은 있어도 "어디를 들어야 하는지"를 모르니 안 듣고, 그래서 다음엔 안 찍는다.

### 측정 전 가설 (0단계에서 확인, §9)

현재 근거는 내 밴드 경험뿐이다. 아래는 전부 **가설**이고, 참관 4팀 + 온라인 설문 30팀(밴드 커뮤니티·합주실 게시판)으로 잰다.

| # | 가설 | 측정 방법 | 통과 기준 | 틀리면 |
| --- | --- | --- | --- | --- |
| H1 | 2시간 합주에서 연주가 멈추는 "다시" 지점이 세션당 10회 이상 | 참관하며 멈춤 시각 기록(스톱워치) | 4팀 중 3팀 | 마커 축 폐기 → 셋리스트·과제 축으로 피벗 |
| H2 | 합주 후 녹음·영상을 10분 이상 다시 보는 멤버는 밴드당 1명 이하 | 설문·인터뷰 | 30팀 중 20팀 이상 | 문제가 없는 것. 중단 검토 |
| H3 | **손으로 자른 30초 클립은 연다.** 참관 중 적은 멈춤 시각으로 클립 5개를 잘라 단톡방에 올리면 72시간 내 멤버 50%가 열고 30%가 2개 이상 듣는다 | 카톡 링크(비공개 유튜브 또는 구글 드라이브) 조회수 + 인터뷰 | 4팀 중 3팀 | **MVP-1 착수 안 함.** "듣기" 가치가 없으므로 텍스트 과제 기록으로 방향 전환 |
| H4 | 셋리스트·녹음을 아무 도구 없이(단톡방만) 관리하는 밴드가 절반 이상 | 설문: "셋리스트 어디에 적나, 녹음 어디 두나, 녹음은 하나" | 30팀 중 15팀 | 노션·시트 밴드가 다수면 그쪽 연동을 2단계로 |
| H5 | 멈춤 후 "왜 멈췄는지" 지시 대화가 20초 안에 끝난다 | 참관 중 멈춤~재개 시간 기록 | 중앙값 20초 이하 | 재생 구간 길이(§4.1)를 측정값으로 조정 |

### 대체재 — 사람들은 지금 무엇으로 버티는가

새 앱은 "갈아타는" 것이 아니라 **하나 더 까는** 것이다. 그래서 "왜 하나 더 까는가"에 답해야 한다. 그리고 가장 큰 경쟁자는 앱이 아니라 **"리뷰를 아예 안 하는 관성"**이다. H3가 이 관성을 재는 가설이다.

| 대체재 | 지금 맡는 것 | 못 하는 것 | 왜 하나 더 까는가 |
| --- | --- | --- | --- |
| 리뷰 안 함 | 아무것도 | 다음 합주가 지난주 반복 | 관성을 이길 만큼 "듣는 비용"이 낮아야 한다. 카드 한 번 → 30초. 그래도 안 열면 H3 실패 |
| 카카오톡 단톡방 | 일정·잡담·링크·파일 공유 | 구조 없음. 일주일 지나면 못 찾음 | 안 깐다. 단톡방은 그대로 두고 **결과를 카톡으로 배달**한다(§4.1). 멤버는 설치 없이 링크만 누른다 |
| **폰 영상 촬영** → 단톡방·비공개 유튜브 | 녹음 + "누가 틀렸는지" 눈으로 보임 | 2시간 영상은 더 안 본다. 유튜브 타임스탬프 댓글은 올린 사람이 손으로 달아야 함 | 영상이 더 정보가 많은 건 맞다. 그래서 **호스트가 영상으로 찍어도 되게** 한다(2단계, 오디오 트랙만 분석). MVP는 오디오로 가설을 먼저 잰다 |
| 아이폰 음성 메모 · 안드로이드 녹음기 | 녹음, 구간 편집 | 편집은 녹음한 사람이 나중에 손으로. 아무도 안 한다 | **마커가 자동으로 찍힌다**는 것이 차이. 단, 이 차별점은 감지율(§7.2)이 통과돼야 성립한다 |
| 네이버 밴드 | 일정·투표·파일·게시판 | 녹음과 시점 연결 없음 | 밴드 앱이 있어도 "어디를 들을지"는 못 준다 |
| 디스코드 | 음성·채팅·파일 | 대학 밴드 일부만 씀. 시점 연결 없음 | 위와 같음 |
| 노션·구글시트 | 셋리스트·곡 목록 | 합주실에서 한 손으로 못 씀. 녹음과 연결 안 됨 | 이걸 이미 잘 쓰는 밴드는 타깃이 아니다(§2) |
| BandHelper · Setlist 계열 앱 | 공연 셋리스트·가사·BPM | 합주 녹음·리뷰 없음. 영어. 공연용 | 합주실 리뷰 축이 없다 |
| BandLab · Soundtrap | 온라인 DAW·협업 녹음 | 합주실 현장과 무관. 과하다 | 과정이 아니라 결과물(트랙) 도구 |
| 합주실 자체 녹음 서비스 | 일부 합주실이 믹서 녹음 제공(유료) | 파일만 준다. 시점 표시 없음 | **앱의 녹음 소스로 활용**한다(2단계). 경쟁이 아니라 입력 |

## 2. 누가, 어떤 순간에

**1차 타깃**: 정기적으로 **합주실을 돈 내고 빌려** 만나는 3~6인 직장인 아마추어 밴드. 서울 홍대·합정·성수·신촌 합주실 상권 중심.

**타깃 아님** (지금은):
- **대학 동아리 밴드** — 무료 동방에서 합주하므로 "시간이 돈"이라는 압력이 약하고, 세대교체로 밴드 단위 누적이 끊긴다. 2단계 이후 별도 검토.
- **노션·시트로 이미 관리하는 밴드** — 이미 도구가 있고 갈아탈 이유가 약하다. H4로 비율을 잰다.
- 프로 세션, 스튜디오 녹음 팀, 원격 실시간 합주를 원하는 사람(§6).

| 사용자 | 순간 | 성공의 모습 |
| --- | --- | --- |
| 리더(보통 기타·보컬). 합주를 멈추는 사람 | 합주 시작 전 | 녹음 전용 폰(예비 폰·태블릿 권장, §10)을 보면대에 세우고 녹음 시작 버튼 하나 |
| 리더 | 연주를 멈추고 "브릿지 앞에서 다시" 하는 순간 | **아무것도 안 한다.** 멈춤이 자동으로 마커가 된다. 여유가 있으면 큰 버튼 한 번으로 "이건 중요" 표시 |
| 모든 멤버 | 다음 날 단톡방 | 카톡에 온 카드에서 "3번째 곡 · 다시 4회" 중 하나를 누르면 멈춤 전 30초 + 지시 대화 20초가 바로 재생된다. 설치·로그인 없이 |
| 리더 | 다음 합주 이틀 전 | 지난 세션의 마커 중 "다음에"를 체크해 이번 주 과제로 옮긴다 |
| 공연 준비 밴드 | 공연 2주 전 | 곡별로 최근 3세션 마커 수 추이를 보고 어디에 남은 합주를 쓸지 정한다(MVP 이후) |

## 3. 다른 앱과 뭐가 다른가

"밴드 앱"으로 묶이는 것들은 대개 **연주 자체**(원격 잼, DAW, 튜너)나 **일정**(네이버 밴드)을 다룬다. 합주노트는 **합주실이라는 두 시간의 결과물**을 다룬다.

1. **마커가 자동이다.** 연주가 멈추면 소리가 준다. 그 지점이 마커 후보다. 누가 손을 뗄 필요가 없다.
2. **결과가 카톡으로 간다.** 멤버는 앱을 깔지 않는다. 카드 하나, 링크 하나, 구간 재생. 카톡은 경쟁자가 아니라 유통 채널이다.
3. **합주 전·중·후가 이어진다** (MVP 이후). 마커 → 과제 → 다음 셋리스트. 이어주는 도구는 없다.

**모방 방어**: 기능 자체는 베낄 수 있다. 남는 것은 밴드별로 쌓이는 세션·마커·과제 이력이고, 유료 플랜의 핵심이 그 이력(§8)이다. 한계도 분명하다. 이력은 밴드가 해체되면 사라지고, 네이버 밴드 같은 큰 플랫폼이 녹음 마커를 붙이면 유통 채널 우위는 그쪽이 갖는다. 그래서 초기 1~2년은 "합주실 씬에서 먼저 익숙한 이름"이 되는 속도 싸움이고, 합주실 제휴(§9 3단계)가 방어선이다. 그래도 지면 진다. 이 프로젝트는 방어 가능한 해자를 전제로 하지 않는다.

## 4. 핵심 기능

### 4.1 MVP-1: 마커 가설만 검증한다

각 기능 옆에 **가설 검증에 필요한가**를 표시한다. N이면 MVP-1에 넣지 않는다.

| 기능 | 내용 | 필요 |
| --- | --- | --- |
| 밴드 만들기 | 이름 하나. 로그인은 호스트(리더)만 카카오 로그인 | Y |
| 세션 녹음 | 호스트 폰 1대. 보면대에 세우고 시작. 화면 켜둠(Wake Lock). 1분 단위 청크로 로컬 저장 | Y |
| 곡 경계 | 녹음 중 "다음 곡" 버튼 한 번 → 곡 경계 타임스탬프. 곡 이름은 나중에 | Y — 마커를 곡 단위로 묶어야 카드가 읽힌다 |
| **멈춤 자동 마커** | 녹음 음량(RMS)이 연주 수준에서 대화 수준으로 3초 이상 떨어지는 지점 → 마커 후보. 세션 시작 시 10초 "대화 수준" 캘리브레이션, 연주 시작 후 연주 수준 자동 갱신. **"다음 곡" 버튼 직전 30초 이내의 멈춤은 곡 종료로 분류해 집계 제외** | Y — 핵심 |
| 손 마커 | 호스트 화면 아래 1/3에 버튼 하나(`중요`) | Y — 자동 감지 실패 대비 보조 |
| 세션 리뷰 | 곡별 마커 목록. 마커 누르면 **멈춤 30초 전 ~ 멈춤 후 20초**(지시 대화 포함) 재생. 두 값은 H5로 조정. 파일은 자르지 않고 재생 위치만 이동 | Y |
| 마커 정리 | 리뷰에서 마커를 `다음에` / `삭제`로만 분류(오탐 제거용). 메모 없음 | Y — 오탐이 카드에 섞이면 멤버가 안 연다 |
| **카톡 공유 카드** | 세션 끝나면 "○○밴드 9/6 합주 · 3곡 · 다시 12회" 카드 링크 생성. 링크는 로그인 없이 리뷰 화면(읽기·재생). 카톡 미리보기용 OG는 서버에서 렌더(§7.1) | Y — 멤버가 실제로 듣는지가 가설 |
| 이벤트 로그 | 카드 열람·마커 재생·리더 녹음 시작을 테이블에 한 줄씩 | Y — 지표 없이는 가설을 못 잰다 |

### 4.2 MVP 이후 (가설이 살아남으면)

| 기능 | 왜 뒤인가 |
| --- | --- |
| 마커 한 줄 메모, `해결` 상태, "다음에" → 다음 셋리스트 과제 자동 승격 | 과제 축. 마커 축이 살아야 의미 있다. **유료 플랜의 핵심 혜택**(§8)이므로 3단계 유료 오픈 전에 만든다 |
| 곡 등록(BPM·키·구조·코드 차트·참고 링크), 곡 상태(제안→연습 중→맞춰봄→공연 가능), 셋리스트 | 셋리스트 축 |
| 멤버 로그인·파트 태그, 멤버 폰에서 마커 | 0단계에서 "손이 비는가" 확인 후. 호스트 1대로 충분하면 영영 안 만든다 |
| 블루투스 페이지터너 페달로 손 마커 | 니치 장비. 손 마커가 실제로 안 눌리는 것으로 확인되면 |
| 영상 녹화 지원(오디오 트랙만 분석), 합주실 믹서 녹음 파일 업로드 | 녹음 소스 다양화. 믹서 파일은 곡 경계·손 마커와 시간축 정렬이 필요(녹음 시작 시각 + 첫 소리 정렬) |
| 시각 메트로놈·카운트인·구조 탭 이동 | 현장 진행 보조. 없어도 마커는 찍힌다 |
| 공연 셋리스트 내보내기, 최근 N세션 마커 추이, 밴드 2개 이상 | 공연 준비·복수 밴드 리더용 |

### 4.3 안 만드는 것
- 합주실 예약·결제 연동 (합주실별 시스템 제각각)
- 멤버별 개별 트랙 녹음, 믹싱, 악보·타브 편집기
- 실시간 원격 합주 (§6)

현장 규칙:
- **녹음 폰은 리더의 주력 폰이 아니어도 된다.** 녹음 중 다른 앱으로 전환하면 iOS는 마이크 캡처가 끊긴다. 온보딩에서 "예비 폰·태블릿·구형 폰"을 권장하고, 주력 폰을 쓸 경우 "2시간 동안 이 폰은 녹음기입니다"를 명시한다.
- **폰 위치**: 보면대 또는 드럼 반대편 벽쪽 선반. 보컬 마이크 스탠드는 피한다(대화 음량이 연주 음량에 근접해 감지가 흔들린다). 주머니는 녹음이 안 되고 앰프 위는 진동이 탄다.
- 360px 폭, 세로 고정, 다크. 글자 최소 18px, 주 버튼 높이 72px, 두 버튼만.
- **소리·진동 없음**. 피드백은 화면 플래시(테두리 색 0.3초). iOS Safari에는 진동 API가 없고, 거치대 위 진동은 녹음에 탄다.
- 화면 꺼짐 방지(Screen Wake Lock, iOS 16.4+). 배터리 경고는 Android(Battery Status API)만. iOS는 온보딩에서 "충전기 연결" 안내.
- 통신은 녹음 중 필요 없다. 업로드는 세션 종료 후, 와이파이 잡히면.

## 6. 왜 실시간 원격 합주를 하지 않는가

- **물리 한계**: 연주자가 어긋남을 못 느끼는 왕복 지연 상한은 대략 20~30ms. 같은 도시 유선에서도 아슬아슬하고, 모바일·와이파이에선 불가능하다. Jamulus·JamKazam이 10년 넘게 매달렸고 여전히 "유선 + 오디오 인터페이스 + 같은 지역"이 전제다.
- **타깃 불일치**: 타깃 밴드는 이미 매주 만난다. 병목은 "함께 연주할 수단"이 아니라 "만났을 때의 결과물"이다.
- **범위**: 1인 개발로 실시간 오디오 네트워킹을 하면 다른 모든 것이 밀린다.

## 7. 기술

### 7.1 스택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 앱 형태 | PWA (React + Vite + TypeScript) | 스토어 심사 없이 배포. 홈 화면 추가. 기존 스택 재사용. 멤버는 링크만 열면 된다 |
| 백엔드 | Supabase (Auth · Postgres · Storage · Edge Functions) | 1인 개발. Realtime은 MVP-1에서 안 쓴다(호스트 1대) |
| **공유 카드 OG 렌더** | Supabase Edge Function이 `/s/:token` 요청에 링크별 OG 메타를 넣은 HTML을 응답 → 이후 SPA 로드 | 카톡 스크래퍼는 정적 index.html의 OG만 읽는다. SPA만으로는 링크별 미리보기가 안 뜬다 |
| 녹음 | MediaRecorder. **iOS Safari: audio/mp4 (AAC)**, Android Chrome: audio/webm (opus). 모노 64kbps | 플랫폼별 지원 포맷이 다르다. `isTypeSupported`로 분기 |
| 마이크 제약 | `echoCancellation: false`, `autoGainControl: false`, `noiseSuppression: false` | 기본값은 통화용. 드럼·앰프를 뭉갠다. 끌 수 없는 기기는 스파이크에서 확인 |
| 로컬 저장 | 1분 청크를 IndexedDB(idb-keyval)에 즉시 저장 | 브라우저가 죽어도 마지막 1분만 잃는다. **청크만으로 복원되는지는 스파이크 항목** |
| 업로드 | Supabase Storage TUS 재개 가능 업로드(청크 6MB 고정) | 지하에서 끊겨도 이어 올린다. 세션 종료 후 와이파이에서 |
| 시킹 | mp4는 문제없음. webm은 duration 메타데이터가 없어 시킹이 깨지므로 청크 병합 시 클라이언트에서 보정 | "30초 전부터 재생"의 전제 |
| 멤버 재생 호환 | Android 호스트의 webm/opus를 iPhone 멤버가 못 틀 수 있다 → 스파이크에서 판정. 실패 시 Edge Function으로는 트랜스코딩이 무거우므로 **호스트 업로드 후 클라이언트에서 AAC 재인코딩**(WebCodecs, Android Chrome) 또는 호스트를 iOS로 제한 | 가설 지표(재생률)를 결정하는 것은 멤버 폰이다 |
| 멈춤 감지 | 녹음과 병렬로 AnalyserNode RMS를 200ms마다 샘플링, 클라이언트에서 저장. 서버 오디오 처리 없음 | Supabase엔 오디오 컴퓨트가 없다. 서버는 파일과 숫자만 받는다 |
| 이력 보존 | 사파리 탭으로 쓰면 "사파리 사용 7일 무상호작용" 시 로컬 저장소가 지워질 수 있다(홈 화면 추가 시 예외). 어느 쪽이든 세션 종료 시 업로드를 끝내는 것이 원칙. 미완료면 홈에 경고 | 로컬은 임시, 서버가 원본 |

### 7.2 기술 스파이크 (0-b, 3주) — 통과 못 하면 MVP 시작 안 함

실제 합주실에서, 실제 밴드 합주 중에 돌린다. 감지율 항목은 **녹음 파일을 노트북에서 사후 분석**(파이썬 스크립트)해 잰다. 앱 안의 실시간 감지는 1단계에서 같은 규칙을 옮겨 심는다.

| 확인 항목 | 통과 기준 |
| --- | --- |
| iOS Safari(최신 2개 버전) + Android Chrome에서 2시간 연속 녹음 | 끊김 0회. 카톡 알림·전화 수신·**앱 전환 후 복귀** 시 마이크 트랙 상태를 기록. 끊기면 "예비 폰 권장 + 방해금지 모드 안내"로 대응 가능한지 판단 |
| 마이크 제약 해제 | 드럼·앰프 구간 클리핑 없음, AGC 펌핑 없음(파형 육안 + 청취) |
| 파일 크기·업로드 | 2시간 ≤ 70MB. 지하에서 시작한 업로드가 지상에서 이어져 완료 |
| **강제 종료 복원** | 녹음 중 브라우저 강제 종료 → IndexedDB 청크만으로 재생·시킹 가능한 파일 복원(iOS mp4 청크 특히) |
| 시킹 정확도 (호스트) | 마커 지점 이동 오차 ±1초 이내 |
| **멤버 기기 재생** | Android 녹음 webm을 iPhone **카톡 인앱 브라우저**에서 열어 마커 지점 시킹 ±1초, LTE에서 첫 재생까지 3초 이내. iOS 녹음 mp4를 Android에서도 |
| **카톡 미리보기** | 링크별 OG(밴드명·날짜·곡 수·마커 수)가 카톡 채팅에 뜸 |
| 멈춤 자동 감지 (사후 분석) | 참관 기록과 대조해 실제 멈춤의 80% 이상 감지, 오탐(곡 중 브레이크·조용한 인트로)은 후보의 50% 이하. 폰 위치 2곳(보면대·벽 선반)에서 각각 |
| 배터리 | 화면 켜둔 채 2시간 녹음 후 잔량 30% 이상(시작 100%) |

실패 시 분기:
- 녹음·복원·배터리 실패 → 녹음 소스를 **합주실 믹서 녹음 파일 업로드** 또는 **영상 촬영 파일 업로드**로 변경(시간축 정렬은 녹음 시작 시각 입력 + 첫 소리 정렬). 그것도 안 되면 중단.
- 멤버 재생 실패 → 호스트를 iOS로 제한하거나 클라이언트 재인코딩 추가(1단계 +1주).
- 감지율 실패 → 손 마커 중심으로 재설계하고 0-a에서 "리더가 멈춘 뒤 버튼을 누를 여유"가 60% 이상인지 확인. 미만이면 마커 축 폐기.

### 7.3 Capacitor 대안의 비용
iOS PWA 녹음이 스파이크를 통과 못 하고 믹서·영상 업로드로도 안 되면 Capacitor 네이티브 래퍼가 마지막 대안이다. 비용: 애플 개발자 계정 연 99달러, 심사 1~2주, 업데이트마다 심사, "스토어 심사 없이 배포"라는 PWA 선택 이유가 사라짐. 호스트(리더)만 설치하면 되므로 감당 가능하지만 로드맵에 3주를 추가한다.

## 8. 수익과 비용

### 8.1 누가 왜 내는가
밴드 단위 결제. 리더 한 명이 결제하고 멤버 전원이 혜택. 합주실비를 이미 회비로 걷고 있어 개인 결제보다 저항이 적다는 것이 가설이다.

유료 혜택은 본문의 가치 명제와 맞춰야 한다. 가치는 "세션 후 72시간 안에 듣는 것"에 있고, 오래된 녹음은 아무도 안 듣는다. 그래서 **보관 기간은 유료 이유가 아니다.** 유료 이유는 **이력이 다음 합주로 이어지는 것**(과제 축)이다.

| 플랜 | 내용 |
| --- | --- |
| 무료 | 밴드 1개, 최근 4세션 리뷰·오디오, 공유 카드 14일 후 만료. 마커·"다음에" 표시는 남음 |
| 밴드 프로 (월 4,900원, 부가세 포함, 가설) | **과제 축**("다음에" → 다음 셋리스트, 곡별 과제, 메모), 세션 이력·오디오 1년(공연 준비 추이), 카드 만료 없음, 믹서·영상 파일 업로드, 밴드 2개 이상 |

유료 오픈(§9 3단계) 전에 과제 축이 만들어져 있어야 한다. 3단계 내용에 넣는다.

### 8.2 숫자의 출처

| 숫자 | 현재 상태 | 채우는 방법 |
| --- | --- | --- |
| 월 4,900원 | 가설. 합주실 2시간 비용(4~6만 원)의 10% 이하로 잡음 | 0-a 설문 문항: "밴드 회비 월 얼마, 도구에 월 얼마까지". 2단계 말 베타 밴드에 가격 3종(2,900·4,900·7,900) 의향 조사 |
| 서울 정기 합주 밴드 수 | **미측정. 0-a 산출물** | 네이버 지도 "합주실" 서울 4개 상권 검색 결과 수 × 합주실당 방 수 × 주말 슬롯 × 정기 밴드 비율(합주실 사장 2명 인터뷰). 3단계 목표 200팀이 이 수의 몇 %인지를 0-a 종료 시 §9에 적는다 |

### 8.3 비용과 손익분기

환율 1,400원/달러로 통일. 밴드당 월 녹음량: 4세션 × 2시간 × 64kbps ≈ 230MB. 재생(이그레스)은 마커 구간만 들으므로 녹음량의 20%로 가정.

| 고정·변동 비용 | 금액 | 근거 |
| --- | --- | --- |
| Supabase Pro | 월 25달러 ≈ 3.5만 원 (100GB 저장·250GB 이그레스 포함) | 공개 요금표 |
| 추가 저장 · 이그레스 | GB당 월 0.021달러 · GB당 0.09달러 | 공개 요금표 |
| 사업자등록 | 0원 (간이과세) | 정기결제 PG 계약 조건 |
| PG 정기결제 | 초기 계약 조건은 PG별 상이(0~수십만 원). 수수료 약 3.3% | 유료 오픈 전 확정 |
| 부가세 | 판매가의 10/110 | 4,900원 중 445원 |
| **밴드당 순매출** | **약 4,300원** | 4,900 − 445(부가세) − 162(수수료) |

| 시나리오 (유료/전체) | 저장량 | 월 비용 | 월 순매출 | 결과 |
| --- | --- | --- | --- | --- |
| 무료 190 + 유료 10 (5%) | 무료 4세션 ≈ 190×230MB = 44GB, 유료 1년 ≈ 10×2.8GB = 28GB → 72GB | 3.5만 원 | 4.3만 원 | 여유 **8천 원**. 손익분기 9팀 |
| 무료 180 + 유료 20 (10%) | 41GB + 56GB = 97GB | 3.5만 원 | 8.6만 원 | 흑자 5.1만 원 |
| 무료 1,000 + 유료 53 (5%) | 230GB + 148GB = 378GB → 초과 278GB × 0.021 = 5.8달러. 이그레스 ≈ 48GB(포함) | 30.8달러 ≈ 4.3만 원 | 22.8만 원 | 흑자 18.5만 원 |

결론과 솔직한 판단:
- 서버비 손익분기는 유료 9팀. 200팀 규모에서는 월 4~8만 원이 남는다. **인건비는 0이다.**
- 이것은 투자 대상이 아니라 **1인 사이드 프로젝트의 생존 조건**이다. 목표는 서버비를 잃지 않으면서 합주실 씬에 자리를 잡는 것이고, 그 이상(합주실 B2B, 밴드 커뮤니티)은 200팀이 확인된 뒤의 이야기다.
- 12개월 내 주간 활성 200팀이 안 나오면 유료화를 접고 무료 도구로 남길지, 중단할지 결정한다(§9 3단계).

## 10. 리스크와 반론

| 반론 | 판단 | 대응 |
| --- | --- | --- |
| **수요 가설을 코드 뒤에 검증한다** | 맞았다. 그래서 바꿨다 | H3: 0-a에서 손으로 자른 클립을 단톡방에 올려 열람·재생을 먼저 잰다. 실패하면 MVP-1을 시작하지 않는다 |
| **합주 중 마커 누를 손이 없다** | 맞다. 기타·베이스는 두 손, 드럼은 스틱, 보컬은 마이크 | 자동 감지가 기본, 손 마커는 보조. 멤버 폰 마커는 뺐다. 감지율 실패 시 0-a에서 "멈춘 뒤 리더가 폰을 누를 여유" 60% 이상인지로 손 마커 중심 재설계 여부 결정 |
| **리더 폰이 2시간 잠긴다** (가사·메트로놈·카톡 불가, 앱 전환 시 iOS 마이크 중단) | 맞다. 호스트 진입 마찰의 최대 요인 | 온보딩에서 예비 폰·태블릿·구형 폰 권장. 앱 전환 복귀 동작은 스파이크 항목. 1단계 통과 기준에 "리더가 4주 중 4주 켰는가"를 넣어 이 마찰을 직접 잰다 |
| **멤버는 앱을 안 연다. 리더가 캡처해서 카톡에 올린다** | 맞다. 그래서 캡처 대신 카드다 | 카톡 안에서 미리보기가 뜨고(Edge Function OG), 링크 하나로 로그인 없이 50초 구간이 재생된다. 열람·재생 비율이 1단계 통과 기준 |
| **멤버 폰에서 재생이 안 된다** (Android webm → iPhone) | 있을 수 있다 | 스파이크에서 카톡 인앱 브라우저로 판정. 실패 시 호스트 iOS 제한 또는 클라이언트 재인코딩 +1주 |
| **녹음 파이프라인이 안 돌아간다** (iOS 2시간, AGC, 업로드, 복원, 시킹) | 가장 위험한 기술 가정 | §7.2 스파이크 3주. 실패 시 믹서·영상 파일 업로드로 소스 변경 |
| **호스트 폰 한 대가 단일 장애점** | 맞다 | 1분 청크 로컬 저장 + 강제 종료 복원을 스파이크로 확인. 2단계에서 밴드 내 누구든 호스트 가능, 믹서 녹음을 대안 소스로 |
| **자동 감지가 오탐·미탐한다** (곡 중 브레이크, 조용한 인트로, 곡 정상 종료) | 있을 것이다 | 곡 종료는 "다음 곡" 버튼 직전 30초 규칙으로 제외. 나머지 오탐은 리뷰에서 삭제 한 번. 오탐 50% 이하가 스파이크 기준. 임계값은 폰 위치 캘리브레이션으로 |
| **폰 영상이 더 낫다** | 정보량은 영상이 많다 | 맞다. 그래서 2단계에 영상 파일 업로드(오디오 트랙 분석)를 넣는다. MVP는 파이프라인이 가벼운 오디오로 가설을 먼저 잰다 |
| **돈이 안 된다** | 맞다. 인건비 0 기준 | 유료 이유를 보관 기간이 아니라 과제 축으로 바꿨다. 5% 전환에서 손익분기 9팀. 12개월 200팀 미달 시 유료화를 접는다는 기준을 미리 둔다. 투자 대상이 아니라 사이드 프로젝트 생존 조건이다 |
| **네이버 밴드가 같은 걸 붙이면** | 유통 우위는 그쪽 | 초기 1~2년 합주실 씬 인지도 + 합주실 제휴(QR·믹서 연동)가 방어선. 그래도 지면 진다 |
| **iOS PWA 녹음 제약** | 스파이크에서 판정 | 통과 못 하면 믹서·영상 업로드 → 그것도 안 되면 Capacitor(§7.3) |
| **합주실 통신 불량** | 지하가 많다 | 녹음 중 통신 불필요. 업로드는 사후·재개 가능 |
| **1인 개발 범위 초과** | 늘 그렇다 | MVP-1은 §4.1 9개 기능, 96시간. 넘기면 빼는 순서를 §9에 미리 적었다 |
