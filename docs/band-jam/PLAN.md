# 합주노트 — 아마추어 밴드의 합주 시간을 아끼는 앱

> 기획안 v1 · 모바일 웹(PWA) · 밴드 단위 공유 · 합주 전·중·후 한 흐름

일주일에 한 번, 두 시간짜리 합주실에서 만나는 아마추어 밴드를 위한 앱.
**합주 전에 뭘 맞출지 정하고, 합주 중에 진행을 놓치지 않고, 합주 후에 "다음에 다시 맞출 것"을 잃어버리지 않게** 한다.

| | |
| --- | --- |
| **합주실 시간은 돈이다** | 시간당 2~3만 원. 그중 30분이 "오늘 뭐 하지"와 "아까 그 부분이 어디였지"에 샌다 |
| **기억은 카톡에 묻힌다** | 합주 끝나고 나온 얘기는 단톡방 스크롤 아래로 사라진다 |
| **녹음은 있는데 못 듣는다** | 폰으로 찍은 2시간짜리 녹음은 아무도 다시 안 튼다 |

---

## 1. 지금은 왜 불편한가

직장인·대학생 아마추어 밴드는 대개 이렇게 움직인다.

- **일정**: 단톡방에서 "이번 주 토 7시 ㅇㅇ합주실?" → 투표 → 누군가 예약
- **곡 선정**: 단톡방에 유튜브 링크 던지기 → 흐지부지 → 합주실 가서 결정
- **합주 중**: "1절부터 다시", "브릿지 전에 드럼 필 어떻게 하기로 했지?" → 그 자리에서 잊음
- **합주 후**: 폰 녹음 2시간짜리 파일을 단톡방에 올림 → 아무도 안 들음
- **다음 합주**: 지난주 얘기했던 걸 다시 처음부터 맞춤

문제는 실력이 아니라 **기억과 진행의 유실**이다. 합주실에서 보내는 두 시간 중 실제로 소리를 내는 시간은 절반 남짓이다.

기존 도구는 이 흐름의 한 조각씩만 맡는다.

| 도구 | 맡는 것 | 못 하는 것 |
| --- | --- | --- |
| 카카오톡 단톡방 | 일정·잡담·링크 | 구조화 안 됨. 일주일 지나면 못 찾음 |
| 노션·구글시트 | 셋리스트·곡 목록 | 합주실에서 한 손으로 못 씀. 녹음과 연결 안 됨 |
| 폰 녹음 앱 | 녹음 | 어느 곡의 어느 부분인지 모름 |
| BandLab·Soundtrap | 온라인 DAW·협업 녹음 | 합주실 현장 진행과 무관. 과하다 |
| 메트로놈·튜너 앱 | 개인 연습 | 밴드 단위 상태 없음 |

## 2. 누가, 어떤 순간에

**타깃**: 정기적으로 합주실을 빌려 만나는 3~6인 아마추어 밴드. 서울 기준 홍대·합정·성수·신촌 합주실 상권을 중심으로 활동하는 직장인 밴드, 동아리 밴드, 공연 준비 밴드.

| 사용자 | 순간 | 성공의 모습 |
| --- | --- | --- |
| 밴드 리더(보통 기타·보컬) | 합주 이틀 전, 이번 주 뭘 맞출지 정한다 | 셋리스트 3곡을 고르고 곡별 "이번 주 과제"를 한 줄씩 남긴다. 멤버가 미리 본다 |
| 드러머 | 합주실에서 곡 넘어갈 때 | 폰 하나로 다음 곡, BPM, 카운트인을 본다. 손이 젖어도 큰 버튼 하나면 된다 |
| 베이시스트 | 합주 중 "여기 다시" 하는 순간 | 버튼 한 번으로 녹음에 마커를 찍는다. 뭐라고 적을 필요 없다 |
| 모든 멤버 | 합주 다음 날 | 녹음 전체가 아니라 마커 찍힌 40초 구간만 듣고, 다음 과제가 뭔지 안다 |
| 공연 준비 밴드 | 공연 2주 전 | 곡별 "완성도" 상태를 보고 어디에 남은 합주 시간을 쓸지 정한다 |

**타깃이 아닌 사람**: 프로 세션, 스튜디오 녹음 팀, 원격에서 실시간으로 함께 연주하려는 사람. 실시간 원격 합주는 §6에서 명시적으로 뺀다.

## 3. 다른 앱과 뭐가 다른가

"밴드 앱"으로 묶이는 것들은 대개 **연주 자체**(원격 잼, DAW, 튜너)를 다룬다. 합주노트는 **합주실이라는 시간·장소**를 다룬다.

핵심 차별점은 셋이다.

1. **합주 전·중·후가 한 흐름이다.** 셋리스트에서 시작해 → 현장 진행 → 녹음 마커 → 다음 과제로 자동 연결된다. 각각을 따로 하는 도구는 있어도 이어주는 도구는 없다.
2. **합주실 현장 UI다.** 어두운 방, 한 손, 땀, 앰프 소리. 큰 글자, 큰 버튼, 다크 기본, 화면 안 꺼짐, 오프라인 동작.
3. **녹음을 "듣게" 만든다.** 2시간 녹음 파일이 아니라 "3번째 곡 브릿지 앞 12초부터" 같은 구간으로 남는다. 마커는 누르는 사람이 아니라 밴드 전체가 공유한다.

## 4. 핵심 기능 (MVP)

### 4.1 밴드 · 멤버
- 밴드 생성 → 초대 링크로 합류. 로그인은 카카오·구글 소셜 로그인.
- 멤버에 파트(보컬·기타·베이스·드럼·키보드·기타) 태그.

### 4.2 곡 · 셋리스트
- 곡 등록: 제목, 원곡자, BPM, 키, 구조(인트로·A·B·코러스·브릿지…), 참고 링크(유튜브), 코드 차트 텍스트.
- 곡별 **상태**: `제안` → `연습 중` → `맞춰봄` → `공연 가능`. 멤버별 "내 파트 준비됨" 체크.
- 이번 합주 **셋리스트**: 곡 순서 + 곡마다 "이번 주 과제" 한 줄 (예: "브릿지 리듬 통일").

### 4.3 합주 세션 (현장 모드) ★
- 세션 시작 → 셋리스트 순서대로 진행. 현재 곡 크게, 다음 곡 작게.
- 곡 화면: BPM 표시 + 시각 메트로놈(깜빡임) + 카운트인 버튼. 구조 표시(지금 어느 파트인지 탭으로 이동).
- **녹음**: 세션 전체를 폰 한 대가 녹음(세션 호스트). 곡 넘길 때 자동으로 곡 경계 타임스탬프.
- **마커 버튼**: 누구든 자기 폰에서 큰 버튼 하나 → 호스트 녹음 타임라인에 마커. 종류는 세 가지만: `다시`, `좋았음`, `얘기함`.
- 화면 꺼짐 방지, 오프라인에서도 진행·마커 동작(나중에 동기화).

### 4.4 합주 후
- 세션 종료 → 곡별로 잘린 녹음 + 마커 목록 자동 생성.
- 마커를 누르면 그 지점 10초 전부터 재생. 마커에 한 줄 메모·담당 파트 태그.
- `다시` 마커는 자동으로 **다음 합주 과제 후보**로 올라간다. 리더가 다음 셋리스트 만들 때 그대로 끌어다 쓴다.

### 4.5 MVP에서 뺀 것
- 합주실 예약·결제 연동 (합주실별 시스템이 제각각. 초기엔 일정과 장소 메모만)
- 멤버별 개별 트랙 녹음, 믹싱
- 악보·타브 편집기 (텍스트 코드 차트로 충분)
- 실시간 원격 합주

## 5. 화면 흐름

```
[홈: 내 밴드]
  └ [밴드 홈]  다음 합주 · 이번 셋리스트 · 최근 세션
       ├ [곡 목록]  상태 필터 · 곡 상세(구조/BPM/링크/코드)
       ├ [셋리스트 편집]  곡 끌어서 순서 · 과제 한 줄
       ├ [세션 진행 ★]  현재 곡 · 메트로놈 · 마커 버튼 · 녹음 상태
       └ [세션 리뷰]  곡별 녹음 · 마커 타임라인 · 다음 과제
```

세션 진행 화면 원칙:
- 360px 폭, 세로 고정, 다크. 글자 최소 18px, 주 버튼 높이 64px 이상.
- 한 손 엄지 영역(화면 아래 1/3)에 `마커`, `다음 곡`. 위쪽은 정보만.
- 소리는 내지 않는다(앰프 소리와 섞임). 메트로놈은 시각·진동.

## 6. 왜 실시간 원격 합주를 하지 않는가

"밴드 합주 앱"이라 하면 흔히 떠올리는 것이 인터넷으로 함께 연주하는 기능이다. 의도적으로 뺀다.

- **물리 한계**: 사람이 어긋남을 못 느끼는 왕복 지연은 약 25ms. 같은 도시 유선에서도 아슬아슬하고, 모바일·와이파이에선 불가능하다. Jamulus, JamKazam이 10년 넘게 이 문제에 매달렸고 여전히 "유선 + 오디오 인터페이스 + 같은 지역"이 전제다.
- **타깃 불일치**: 아마추어 밴드의 병목은 "같이 연주할 수단"이 아니라 "만났을 때의 시간 효율"이다. 이들은 이미 매주 만난다.
- **범위**: 1인 개발로 실시간 오디오 네트워킹까지 하면 다른 모든 것이 밀린다.

## 7. 기술

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 앱 형태 | PWA (React + Vite + TypeScript) | 스토어 심사 없이 배포. 홈 화면 추가로 앱처럼. 기존 스택 재사용 |
| 백엔드 | Supabase (Auth · Postgres · Storage · Realtime) | 1인 개발. 밴드 단위 공유·녹음 파일 저장·마커 실시간 전파를 직접 안 짜도 됨 |
| 녹음 | MediaRecorder API (webm/opus) | 브라우저 표준. 세션 종료 후 Storage 업로드 |
| 마커 실시간 전파 | Supabase Realtime (브로드캐스트) | 멤버 폰 → 호스트 폰 마커 전달. 오프라인 시 로컬 큐 → 재접속 시 전송 |
| 오프라인 | IndexedDB 로컬 우선, 재접속 동기화 | 지하 합주실은 통신이 안 좋다 |
| 시간 동기 | 세션 시작 시 호스트 기준 오프셋 계산 | 마커 타임스탬프를 호스트 녹음 시간축에 맞춤 |

iOS Safari 제약(백그라운드 녹음 중단, PWA 오디오 제한)은 MVP에서 "녹음은 호스트 폰 화면 켜둔 채"로 우회한다. 문제가 되면 호스트용 네이티브 래퍼(Capacitor)를 2단계에서 검토한다.

## 8. 수익 모델

- **무료**: 밴드 1개, 곡 20개, 녹음 보관 30일.
- **밴드 프로 (월 4,900원, 밴드당)**: 곡 무제한, 녹음 보관 무제한, 세션 리뷰 공유 링크, 공연 셋리스트 내보내기.
- 결제는 밴드 단위 한 명이 하고 멤버 전원이 혜택. 밴드 회비에서 나가는 돈이라 개인 결제보다 저항이 적다.

초기 목표는 수익이 아니라 **활성 밴드 수**다. 1년 내 주간 활성 밴드 200팀이면 유료 전환 10%로 월 100만 원. 1인 운영 서버비를 넘기는 선.

## 10. 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 리더 혼자 쓰고 멤버는 안 깐다 | 멤버는 로그인 없이 초대 링크로 마커·셋리스트 열람 가능. 로그인은 메모 남길 때만 |
| 녹음 품질이 나빠서 안 듣는다 | 목표는 "판단 가능한" 품질이지 음원이 아니다. 마커 구간만 듣기 때문에 길이 부담이 없다 |
| iOS PWA 녹음 제약 | 호스트 폰은 화면 켜둠. 안 되면 Capacitor 래퍼 |
| 노션·시트로 이미 잘 쓰는 밴드 | 그 밴드는 타깃이 아니다. 아무것도 안 쓰는 밴드가 대다수 |
| 합주실 통신 불량 | 오프라인 우선. 마커는 로컬 저장 후 동기화 |
| 1인 개발 범위 초과 | MVP를 §4로 고정. 예약·DAW·원격 합주는 명시적으로 뺌 |
