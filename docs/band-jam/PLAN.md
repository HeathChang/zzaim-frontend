# 합주노트 — 합주실에서 "여기 다시"를 잃어버리지 않는 앱

> 기획안 v5 · 모바일 웹(PWA) · 호스트 폰 1대로 시작 · 코드 전에 손으로 수요 검증

일주일에 한 번, 두 시간짜리 합주실을 빌려 만나는 아마추어 밴드를 위한 앱.
합주 중 연주가 멈춘 지점을 녹음에 자동으로 표시하고, 다음 날 그 구간만 다시 들으며 "다음에 맞출 것"을 남긴다.

| | |
| --- | --- |

## 1. 지금은 왜 불편한가

직장인 아마추어 밴드는 대개 이렇게 움직인다.

- **일정**: 단톡방에서 "이번 주 토 7시 ㅇㅇ합주실?" → 투표 → 누군가 예약
- **곡 선정**: 단톡방에 유튜브 링크 던지기 → 합주실 가서 결정
- **합주 중**: "브릿지 앞에서 다시" → 몇 번 맞추고 넘어감 → 그 자리에서 잊음
- **합주 후**: 폰 녹음·영상 2시간짜리를 단톡방에 올림 → 아무도 안 봄. 아예 안 찍는 밴드도 많다
- **다음 합주**: 지난주 얘기했던 걸 다시 처음부터 맞춤

문제는 실력이 아니라 **기억의 유실**이다. 녹음은 있어도 "어디를 들어야 하는지"를 모르니 안 듣고, 그래서 다음엔 안 찍는다.

### 근거의 현재 상태

솔직히 적는다. **현재 정량 근거는 0이다.** 기획자 본인 밴드 경험에서 나온 인상뿐이다. 이 문서는 근거를 지어내지 않고, 0-a 첫 주에 아래 표부터 채운다. 표가 채워지기 전까지 이 기획안의 문제 정의는 가설이다.

### 측정 전 가설 (0단계에서 확인, §9)

참관 4팀(내 밴드 + 지인 3팀. 편향은 인정하고, 설문 30팀으로 보완) + 온라인 설문 30팀(밴드 커뮤니티·합주실 게시판)으로 잰다.

### 대체재 — 사람들은 지금 무엇으로 버티는가

새 앱은 "갈아타는" 것이 아니라 **하나 더 까는** 것이다. 멤버에게는 "왜 하나 더 여는가", 리더에게는 "지금 하던 것보다 얼마나 더 무거운가"에 답해야 한다. 가장 큰 경쟁자는 앱이 아니라 **"리뷰를 아예 안 하는 관성"**이다. H3·H6이 이 관성을 재는 가설이다.

| 대체재 | 지금 맡는 것 | 못 하는 것 | 멤버: 왜 하나 더 여는가 | 리더: 전환 비용 |
| --- | --- | --- | --- | --- |
| 리뷰 안 함 | 아무것도. 비용 0 | 다음 합주가 지난주 반복 | 카드 한 번 → 리더 픽 3개 = 2.5분. 그래도 안 열면 H3 실패 | 0 → 주 3동작(§5.1). 이 차이를 H6이 잰다 |
| 단톡방에 "브릿지 다시" 한 줄 적기 | 기억 보조, 비용 거의 0 | 소리가 없다. 스크롤에 묻힘 | 한 줄 메모는 앱 안에서도 되고("다음에"), 거기에 소리가 붙는다 | 한 줄 적기 vs 폰 세우기. 후자가 무겁다 |
| 카카오톡 단톡방 | 일정·잡담·링크·파일 공유 | 구조 없음. 일주일 지나면 못 찾음 | 안 깐다. 단톡방은 그대로 두고 **결과를 카톡으로 배달**한다 | 없음(카톡은 그대로) |
| 아이폰 음성 메모 · 안드로이드 녹음기 | 녹음, 구간 편집. **주머니 속 주력 폰에서 백그라운드로 돈다** | 편집은 나중에 손으로. 아무도 안 한다 | **마커가 자동으로 찍힌다.** 단, 감지율(§7.2)이 통과돼야 성립 | **가장 큰 전환 비용.** 예비 폰을 세우고, 화면을 2시간 켜고, 그 폰으로 다른 앱을 못 연다. 그래서 H6은 이 조건 그대로 잰다 |
| **클로바노트** (녹음·북마크·공유 링크·자동 텍스트, 무료) | 회의 녹음. 녹음 중 북마크, 링크 공유 | 음악은 전사가 안 되고, 곡 단위 묶음·멈춤 전후 구간 재생·다음 합주 연결이 없다. 백그라운드 녹음은 된다 | 곡별 집계 + 50초 구간창 + "다음에"가 다음 합주에 뜸 | 클로바노트가 더 가볍다. 자동 마커·곡 집계가 없으면 이쪽이 이긴다(§3) |
| 삼성 음성 녹음 북마크 · Zoom H1n 마크 버튼 | 녹음 중 손 마커 | 기기 안에만 남는다 | 공유·구간 재생·다음 합주 연결 | 레코더는 별도 장비, 삼성은 백그라운드 가능 |

| 합주실 자체 녹음 서비스 | 믹서 녹음 제공(유료) | 파일만 준다 | **앱의 녹음 소스로 활용**(2단계) | 리더 부담 0. 이게 되면 가장 좋다 |

## 2. 누가, 어떤 순간에

**1차 타깃**: 정기적으로 **합주실을 돈 내고 빌려** 만나는 3~6인 직장인 아마추어 밴드. 서울 홍대·합정·성수·신촌 합주실 상권 중심.

**타깃 아님** (지금은):
- **대학 동아리 밴드** — 무료 동방에서 합주하므로 "시간이 돈"이라는 압력이 약하고, 세대교체로 밴드 단위 누적이 끊긴다. 2단계 이후 별도 검토.
- **노션·시트로 이미 관리하는 밴드** — 이미 도구가 있고 갈아탈 이유가 약하다. H4로 비율을 잰다.
- 프로 세션, 스튜디오 녹음 팀, 원격 실시간 합주를 원하는 사람(§6).

**진짜 사용자는 리더다.** 멤버는 링크를 누를 뿐이고, 매주 폰을 세우고 버튼을 누르고 공유하는 사람은 리더 한 명이다. 리더의 주간 부담은 §5에서 3동작으로 압축하고, H6으로 코드 전에 **앱과 같은 조건에서** 잰다.

| 사용자 | 순간 | 성공의 모습 |
| --- | --- | --- |
| 리더(보통 기타·보컬). 합주를 멈추는 사람 | 합주 시작 전 | 녹음 전용 폰(예비 폰·태블릿)을 보면대에 세우고 녹음 시작 버튼 하나 |
| 리더 | 연주를 멈추고 "브릿지 앞에서 다시" 하는 순간 | **아무것도 안 한다.** 멈춤이 자동으로 마커가 된다. 여유가 있으면 큰 버튼 한 번으로 "이건 중요" 표시 |
| 리더 | 합주 종료 버튼을 누른 직후 | 지난주 "다음에" 목록이 뜨고, 오늘 맞춰본 것을 체크한다(30초) |
| 리더 | 합주 끝나고 지상에서 | 와이파이 잡히면 자동 업로드. 다음 날 아침 알림 → 카드 훑고(3분) → 공유 버튼 한 번 |
| 모든 멤버 | 다음 날 단톡방 | 카톡에 온 카드 "성현밴드 9/6 합주 · 곡 3개 · 리더 픽 3 · 다시 12"를 누르면 리더 픽 3개가 맨 위, 하나 누르면 50초 재생. 설치·로그인 없이 |
| 공연 준비 밴드 | 공연 2주 전 | 곡별로 최근 3세션 마커 수 추이를 보고 어디에 남은 합주를 쓸지 정한다(MVP 이후) |

## 3. 다른 앱과 뭐가 다른가

"밴드 앱"으로 묶이는 것들은 대개 **연주 자체**(원격 잼, DAW, 튜너)나 **일정**(네이버 밴드)을 다룬다. 합주노트는 **합주실이라는 두 시간의 결과물**을 다룬다.

1. **마커가 자동이다.** 연주가 멈추면 소리가 준다. 그 지점이 마커 후보다. 누가 손을 뗄 필요가 없다.
2. **결과가 카톡으로 간다.** 멤버는 앱을 깔지 않는다. 카드 하나, 링크 하나, 구간 재생. 카톡은 경쟁자가 아니라 유통 채널이다.
3. **합주 전·중·후가 이어진다.** "다음에" 마커가 다음 세션 종료 화면에 체크리스트로 뜬다(MVP-1). 과제·셋리스트로 확장(MVP 이후).

**감지율이 실패하면 무엇이 남는가.** 손 마커 + 공유 링크만 남으면 클로바노트·삼성 북마크와의 차이는 "곡 단위 집계·50초 구간창·다음 합주 연결" 세 가지뿐이고, 그 셋은 얇다. 그 경우 이 앱은 셋리스트·과제 축 없이는 존재 이유가 없으므로, §7.2 감지율 실패 분기는 "손 마커로 계속"이 아니라 **"과제 축 중심으로 피벗하고 녹음은 부속으로"**다.

**모방 방어**: 기능 자체는 베낄 수 있다. 남는 것은 밴드별로 쌓이는 세션·마커·과제 이력이고, 유료 플랜의 핵심이 그 이력(§8)이다. 한계도 분명하다. 이력은 밴드가 해체되면 사라지고(§10), 네이버 밴드 같은 큰 플랫폼이 녹음 마커를 붙이면 유통 채널 우위는 그쪽이 갖는다. 초기 1~2년은 "합주실 씬에서 먼저 익숙한 이름"이 되는 속도 싸움이고, 합주실 제휴(§9)가 방어선이다. 그래도 지면 진다. 이 프로젝트는 방어 가능한 해자를 전제로 하지 않는다.

## 4. 핵심 기능

### 4.1 MVP-1: 마커 가설만 검증한다

각 기능 옆에 **가설 검증에 필요한가**를 표시한다. N이면 MVP-1에 넣지 않는다.

| 기능 | 내용 | 필요 |
| --- | --- | --- |
| 밴드 만들기 | 이름 하나. **로그인 없음.** 호스트는 기기 로컬 토큰 + 8자리 복구 코드로 식별. 소셜 로그인은 2단계 | Y — 식별은 필요, 로그인은 불필요 |
| 세션 녹음 | 호스트 폰 1대. 보면대에 세우고 시작. 화면 켜둠(Wake Lock). 1분 단위 청크로 로컬 저장 | Y |
| 곡 경계 | 녹음 중 [다음 곡] 버튼 한 번 → 곡 경계 확정. **버튼 직전의 마지막 멈춤은 곡 종료로 확정**(시간 임계값보다 우선). 곡 이름은 리뷰에서 입력(선택, 미입력 시 "곡 3") | Y — 곡 단위 묶음 + 곡 종료 분류의 1차 근거 |
| **멈춤 자동 마커** | 200ms RMS. 세션 시작 시 10초 "대화 수준" 캘리브레이션, 연주 시작 후 "연주 수준" 자동 갱신. **연주 수준 대비 −20dB(초기값) 이하가 3초 이상** → 멈춤 후보. **버튼을 안 눌렀을 때만** 시간 임계값으로 곡 종료 분류: 대화 지속이 **H5에서 잰 멈춤 대화 분포의 90퍼센타일**을 넘으면 곡 종료. 노들링(멈춤 사이 기타·드럼 딸깍임)으로 −20dB까지 안 떨어지는 미탐은 **대화 대역(300Hz~3kHz) 에너지 비율**을 보조 신호로 쓰고, 그래도 놓치면 손 마커가 보완 | Y — 핵심 |
| 손 마커 | 호스트 화면 아래 1/3에 버튼 하나(`중요`). 리뷰에서 "리더 픽"으로 카드 상단에 감 | Y — 자동 감지 실패 대비 보조 + 카드 우선순위 |
| 세션 종료 화면 | [종료] 누르면 지난 세션 "다음에" 목록이 체크리스트로 뜸 → "맞춰봄" 체크(30초) | Y — 가설 후반("다음 합주가 달라진다")의 자가 보고 지표 |
| 세션 리뷰 (호스트) | 곡별 마커 목록. 곡 이름 입력(선택). 마커를 `다음에` / `삭제`로 분류(오탐 제거). 마커 누르면 **멈춤 30초 전 ~ 멈춤 후 20초** 재생(두 값은 H5로 조정). 파일은 자르지 않고 재생 위치만 이동. **목표 소요: 마커 12개 기준 3분** | Y — 오탐이 카드에 섞이면 멤버가 안 연다 |
| **카톡 공유 카드** | 업로드 완료 시 카드 링크 생성. 표시 문자열: `성현밴드 9/6 합주 · 곡 3개 · 리더 픽 3 · 다시 12`. **리더 픽(손 마커·"다음에")이 맨 위**, 나머지는 곡별 접힘. 링크는 로그인 없이 리뷰 화면(읽기·재생). OG는 서버에서 렌더(§7.1). 링크 만료 기본 30일, 리더가 즉시 만료 가능 | Y — 멤버가 실제로 듣는지가 가설 |
| 자동 업로드 + 아침 알림 | 세션 종료 후 와이파이 감지 시 자동 업로드. 완료되면 다음 날 08:00 PWA 푸시(iOS 16.4+ 홈 화면 추가 시) "카드 준비됨 → 공유" | Y — 리더 부담을 줄이지 않으면 4주를 못 간다 |
| 이벤트 로그 | 녹음 시작·업로드 완료·카드 발송·카드 열람·마커 재생·"맞춰봄" 체크를 테이블에 한 줄씩. **재발 지표**: "다음에" 마커의 (곡, 곡 내 위치 ±10%)에 다음 세션 멈춤이 다시 있는지 자동 계산 | Y — 지표 없이는 가설을 못 잰다. 재발 지표는 자가 보고를 보완하는 객관 지표 |

## 5. 화면 흐름 (MVP-1)

### 5.1 호스트(리더)

```
[호스트 홈]  내 밴드 · 최근 세션 · (업로드 미완료 경고)
   ├ [녹음 ★]   ● 녹음 중 12:34 · 곡 2 · 마커 7
   │             ┌──────────────────────────┐
   │             │  (정보: 시간·곡·마커 수)   │
   │             │                          │
   │             ├──────────────────────────┤ ← 아래 1/3
   │             │   [ 중요 ]   [ 다음 곡 ]   │   버튼 높이 72px
   │             └──────────────────────────┘
   ├ [종료 화면]  지난주 다음에 (3)  ☑ 맞춰봄 ☐ ☐   → [완료]
   └ [세션 리뷰]  리더 픽 · 곡별 마커 · 곡 이름(선택) · ▶ 50초 · 다음에/삭제 · [카톡 공유]
```

**리더의 주간 부담을 3동작으로 압축한다.** 대체재("리뷰 안 함")의 부담은 0이고, 음성메모는 주머니 속에서 돈다. 이 3동작 + 예비 폰 조건이 4주 이상 유지되는지가 H6과 1단계 통과 기준이다.

| 동작 | 리더가 하는 것 | 목표 시간 | 앱이 하는 것 |
| --- | --- | --- | --- |
| 1. 합주 시작 | 예비 폰 세우고 [녹음] | 30초 | 캘리브레이션, Wake Lock, 청크 저장 |
| 2. 합주 중·종료 | 곡 넘어갈 때 [다음 곡] (안 눌러도 됨) · [종료] 후 "맞춰봄" 체크 | 30초 | 멈춤 감지, 곡 종료 분류 |
| 3. 다음 날 아침 | 알림 → 카드 훑고 오탐 삭제(선택) → [카톡 공유] | **3분** | 와이파이 자동 업로드, 카드 생성, 08:00 알림 |

**세션 종료 → 카드 발송 시간축** (목표: 종료 후 **12시간 내** 발송, 1단계 지표)

```
21:00 합주 종료 ─ 지하, 통신 없음
21:30 지상·와이파이 → 자동 업로드 시작(R2 멀티파트, 재개 가능)
22:00 업로드 완료 → 카드 생성 (오탐 정리 전 상태로도 발송 가능)
08:00 다음 날 푸시 "카드 준비됨" → 리더가 3분 훑고 공유  ← 72시간 창의 앞 11시간 사용
```

현장 규칙:
- **녹음 폰은 예비 폰·태블릿·구형 폰.** 녹음 중 다른 앱으로 전환하면 iOS는 마이크 캡처가 끊긴다. 주력 폰을 쓸 경우 "2시간 동안 이 폰은 녹음기입니다"를 온보딩에서 명시한다. 예비 폰 보유율은 H4 설문 항목.
- **폰 위치**: 보면대 또는 드럼 반대편 벽쪽 선반. 보컬 마이크 스탠드는 피한다(대화 음량이 연주 음량에 근접해 감지가 흔들린다). 주머니는 녹음이 안 되고 앰프 위는 진동이 탄다.
- 360px 폭, 세로 고정, 다크. 글자 최소 18px, 주 버튼 높이 72px, 두 버튼만.
- **소리·진동 없음**. 피드백은 화면 플래시(테두리 색 0.3초). iOS Safari에는 진동 API가 없고, 거치대 위 진동은 녹음에 탄다.
- 화면 꺼짐 방지(Screen Wake Lock, iOS 16.4+). 배터리 경고는 Android(Battery Status API)만. iOS는 온보딩에서 "충전기 연결" 안내.
- 통신은 녹음 중 필요 없다. 업로드는 세션 종료 후, 와이파이 잡히면 자동.

### 5.2 멤버 (카톡 → 인앱 브라우저, 로그인 없음)

```
[카톡 카드]  OG: "성현밴드 9/6 합주 · 곡 3개 · 리더 픽 3 · 다시 12"  ← 누르면
   ↓
[리뷰 (읽기)]  리더 픽 (3)                       ← 최소 듣기 = 3 × 50초 = 2.5분
                 ▶ 곡 2 「곡 이름」 12:34  50초
                 ▶ …
               곡 1 · 다시 4  (접힘)
               곡 2 · 다시 5  (접힘)
   ↓ 하나 누르면
[재생]  진행 바(0~50초) · 곡·마커 번호 · [다음 마커 ▶]  · 자동으로 다음 마커로 넘어감
```

- **첫 재생 3초 이내**(LTE): 파일은 moov를 앞에 둔 mp4(remux 시 faststart), 재생은 Range 요청으로 구간만 받는다(50초 ≈ 400KB). 카드 열람 시 리더 픽 1번 구간을 미리 받아 둔다.
- 카톡 인앱 브라우저에서 동작해야 한다(외부 브라우저 열기 요구 금지).
- 멤버 화면에는 쓰기 없음.
- 녹음 동의: 카드 첫 화면 하단에 "이 녹음은 ○○밴드 멤버만 보라고 리더가 공유했습니다. 링크 만료 ○월 ○일". 리더는 리뷰 화면에서 즉시 만료 가능.

## 6. 왜 실시간 원격 합주를 하지 않는가

- **물리 한계**: 연주자가 어긋남을 못 느끼는 왕복 지연 상한은 대략 20~30ms. 같은 도시 유선에서도 아슬아슬하고, 모바일·와이파이에선 불가능하다. Jamulus·JamKazam이 10년 넘게 매달렸고 여전히 "유선 + 오디오 인터페이스 + 같은 지역"이 전제다.
- **타깃 불일치**: 타깃 밴드는 이미 매주 만난다. 병목은 "함께 연주할 수단"이 아니라 "만났을 때의 결과물"이다.
- **범위**: 1인 개발로 실시간 오디오 네트워킹을 하면 다른 모든 것이 밀린다.

## 7. 기술

### 7.1 스택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 앱 형태 | PWA (React + Vite + TypeScript) | 스토어 심사 없이 배포. 홈 화면 추가. 기존 스택 재사용. 멤버는 링크만 열면 된다 |
| 호스팅 · 공유 링크 도메인 | Cloudflare Pages (무료, 커스텀 도메인 무료) | Supabase Edge Function 기본 URL은 `*.supabase.co/functions/v1/...`이라 공유 링크로 쓰기 어렵고 커스텀 도메인은 월 10달러. Pages Functions가 같은 도메인에서 OG를 렌더한다 |
| **공유 카드 OG 렌더** | Cloudflare Pages Function이 `/s/:token` 요청에 링크별 OG 메타를 넣은 HTML을 응답 → 이후 SPA 로드 | 카톡 스크래퍼는 서버가 준 HTML의 OG만 읽는다. SPA만으로는 링크별 미리보기가 안 뜬다 |
| DB · 푸시 | Supabase (Postgres · Edge Functions for 푸시 발송). **0~2단계 Free, 3단계 공개 시 Pro** | Free 한도(DB 500MB, Edge Function 50만 호출, MAU 5만)는 100팀 규모에서 안 걸린다. Free의 실제 문제는 **7일 무활동 시 프로젝트 일시정지**와 **백업 없음**이다. 주 1회 사용이면 정지는 안 되지만, 공개 후 밴드 녹음 이력을 백업 없이 두는 것은 안 된다 → 3단계부터 Pro |
| **오디오 저장** | Cloudflare R2 (월 10GB 무료, 이후 GB당 0.015달러, **이그레스 무료**) | 재생 트래픽이 비용에 안 잡힌다 |
| **업로드 경로** | 클라이언트 → Pages Function이 R2 멀티파트 **presigned URL** 발급 → 클라이언트가 파트(5MB 이상) 직접 업로드, 재개 가능. TUS 아님 | R2는 TUS를 지원하지 않는다. 브라우저에서 R2에 직접 쓰려면 서명 발급 계층이 필요하다 |
| 녹음 | MediaRecorder. **iOS Safari: audio/mp4 (AAC)**. **Android Chrome: `isTypeSupported('audio/mp4')`를 먼저 확인**(Chrome 126+ 플랫폼 인코더 시 지원) → 되면 mp4, 안 되면 webm/opus. 모노 64kbps | mp4로 통일되면 재인코딩 분기가 통째로 사라진다 |
| 마이크 제약 | `echoCancellation: false`, `autoGainControl: false`, `noiseSuppression: false` | 기본값은 통화용. 드럼·앰프를 뭉갠다. 끌 수 없는 기기는 스파이크에서 확인 |
| 로컬 저장 | 1분 청크를 IndexedDB(idb-keyval)에 즉시 저장. **목표: 브라우저가 죽어도 마지막 1분만 잃는 것. 스파이크 통과 전까지 미검증** | 로컬은 임시, 서버가 원본 |
| **청크 독립성** | webm은 첫 청크에만 EBML 헤더가 있고, Safari mp4는 stop() 이전 청크의 재생 가능 여부가 불확실 → 헤더 청크 별도 보존 + 복원 시 remux(faststart) 방식을 스파이크 산출물로 확정 | "1분만 잃는다"의 전제 |
| 시킹 | mp4는 faststart remux로 문제없음. webm은 duration 메타데이터가 없어 시킹이 깨지므로 청크 병합 시 클라이언트에서 보정 | "30초 전부터 재생"의 전제 |
| 멤버 재생 호환 | Android webm/opus를 iPhone 멤버가 못 틀 수 있다 → 스파이크에서 판정. Android mp4가 지원되면 문제 소멸. 아니면 **호스트 업로드 후 클라이언트에서 AAC 재인코딩**(WebCodecs, Android Chrome) 또는 호스트 iOS 제한 | 가설 지표(재생률)를 결정하는 것은 멤버 폰이다 |
| 멈춤 감지 | 녹음과 병렬로 AnalyserNode RMS + 대화 대역 에너지 비율을 200ms마다 샘플링, 클라이언트에서 저장. 서버 오디오 처리 없음 | 서버는 파일과 숫자만 받는다 |
| 이력 보존 | 사파리 탭으로 쓰면 "사파리 사용 7일 무상호작용" 시 로컬 저장소가 지워질 수 있다(홈 화면 추가 시 예외). 어느 쪽이든 세션 종료 시 업로드를 끝내는 것이 원칙. 미완료면 홈에 경고 | 로컬은 임시 |
| 푸시 | Web Push. iOS는 16.4+ 홈 화면 추가 시만 | 미지원이면 리더에게 "다음 날 아침 카드 확인" 온보딩 안내로 대체 |

### 7.2 기술 스파이크 (0-b, 7주 · 주 6시간 = 42시간) — 통과 못 하면 MVP 시작 안 함

실제 합주실에서, 실제 밴드 합주 중에 돌린다. **구축과 측정을 분리**한다. 구축한 것은 1단계에서 그대로 재사용하며, 재사용분은 §9 1단계 시간표에서 뺀다. 감지율은 녹음 파일을 노트북에서 사후 분석한다. 0-b 1~2주차 산출물(녹음 페이지)이 H6 실험의 도구가 되므로 0-b가 0-a보다 먼저 시작한다.

### 7.3 Capacitor 대안의 비용
iOS PWA 녹음이 스파이크를 통과 못 하고 믹서·영상 업로드로도 안 되면 Capacitor 네이티브 래퍼가 마지막 대안이다. 비용: 애플 개발자 계정 연 99달러(≈14만 원), 심사 1~2주, 업데이트마다 심사, "스토어 심사 없이 배포"라는 PWA 선택 이유가 사라짐. 호스트(리더)만 설치하면 되므로 감당 가능하지만 로드맵에 3주를 추가한다.

## 8. 수익과 비용

### 8.1 누가 왜 내는가
밴드 단위 결제. 리더 한 명이 결제하고 멤버 전원이 혜택. 합주실비를 이미 회비로 걷고 있어 개인 결제보다 저항이 적다는 것이 가설이다.

유료 혜택은 본문의 가치 명제와 맞춰야 한다. 가치는 "세션 후 72시간 안에 듣는 것"에 있고, 오래된 녹음은 아무도 안 듣는다. 그래서 **보관 기간은 유료 이유가 아니다.** 유료 이유는 **이력이 다음 합주로 이어지는 것**(과제 축)이다.

| 플랜 | 내용 |
| --- | --- |
| 무료 | 밴드 1개, 최근 4세션 리뷰·오디오(5번째 세션부터 오래된 오디오 삭제, 마커·"다음에"는 남음), 공유 카드 30일 후 만료 |
| 밴드 프로 (월 4,900원, 부가세 포함, 가설) | **과제 축**("다음에" → 다음 셋리스트, 곡별 과제, 메모), 세션 이력·오디오 1년(공연 준비 추이), 카드 만료 없음, 믹서·영상 파일 업로드, 밴드 2개 이상 |

**지불 의향은 기능이 있어야 잴 수 있다.** 2단계 베타에 과제 축의 수동 버전("다음에" 목록을 다음 세션 셋리스트로 복사, 메모 한 줄)을 먼저 넣고, 베타 말에 실제 결제 링크(월 4,900원)를 연다. n=15에서 1팀 = 6.7%이므로 전환율을 판정할 수는 없다. **판정 규칙**: 0팀이면 실패(3단계 유료 오픈 보류, 지불 이유 재설계). 1팀 이상이면 "왜 냈는가 / 왜 안 냈는가" 인터뷰 15건으로 보완 판정하고, 전환율은 3단계 첫 3개월(활성 50팀 이상 시점)에 잰다.

**3단계 획득 산식** (정기 밴드는 매주 같은 슬롯을 쓰므로 "주당 신규"가 아니라 **고유 밴드 풀 × 전환율 = 누적**, 그리고 **활성 = 누적 ÷ 1.5**)

즉 기본 목표 90팀은 "제휴 12곳 + QR 25%"가 모두 맞아야 나오고, 그때 Pro 손익분기(유료 10팀)는 **전환 11%**를 요구한다. 5%면 유료 4~5팀으로 Pro 유지가 안 되고 Free로 내린다. 이 숫자를 숨기지 않는다.
