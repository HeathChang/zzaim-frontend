# 합주노트 — 합주실에서 "여기 다시"를 잃어버리지 않는 앱

> 기획안 v2 · 모바일 웹(PWA) · 호스트 폰 1대로 시작 · 합주 전·중·후 한 흐름

일주일에 한 번, 두 시간짜리 합주실을 빌려 만나는 아마추어 밴드를 위한 앱.
합주 중 연주가 멈춘 지점을 녹음에 자동으로 표시하고, 다음 날 그 구간만 다시 들으며 "다음에 맞출 것"을 남긴다.

| | |
| --- | --- |
| **핵심 가설 하나** | "합주 중 멈춘 지점만 다시 들을 수 있으면, 밴드는 녹음을 실제로 듣고 다음 합주가 달라진다" |
| **MVP는 이 가설만 검증한다** | 호스트 폰 1대 · 녹음 · 멈춤 지점 마커 · 그 구간 재생 · 카톡 공유 카드. 그 외는 전부 뒤로 |
| **가장 위험한 것부터 확인한다** | 모바일 브라우저 2시간 녹음이 되는지를 코드 한 줄 쓰기 전에 1주 스파이크로 확인 |

---

## 1. 지금은 왜 불편한가

직장인 아마추어 밴드는 대개 이렇게 움직인다.

- **일정**: 단톡방에서 "이번 주 토 7시 ㅇㅇ합주실?" → 투표 → 누군가 예약
- **곡 선정**: 단톡방에 유튜브 링크 던지기 → 합주실 가서 결정
- **합주 중**: "브릿지 앞에서 다시" → 몇 번 맞추고 넘어감 → 그 자리에서 잊음
- **합주 후**: 폰 녹음 2시간짜리 파일을 단톡방에 올림 → 아무도 안 들음
- **다음 합주**: 지난주 얘기했던 걸 다시 처음부터 맞춤

문제는 실력이 아니라 **기억의 유실**이다. 녹음은 있는데 "어디를 들어야 하는지"를 모르니 안 듣는다.

**측정 전 가설** (0단계에서 스톱워치로 확인, §9):

| 가설 | 측정 방법 | 이 가설이 틀리면 |
| --- | --- | --- |
| 2시간 합주에서 연주가 멈추는 "다시" 지점이 곡당 3회 이상, 세션당 10회 이상 | 참관하며 멈춤 횟수·시각 기록 | 마커 축 폐기, 셋리스트·과제 축으로 피벗 |
| 합주 후 녹음을 끝까지 듣는 멤버는 밴드당 1명 이하 | 인터뷰: "지난 녹음 들었나, 몇 분 들었나" | 문제 자체가 없는 것. 프로젝트 중단 검토 |
| "지난주 얘기한 것"을 다음 합주에서 다시 찾는 데 곡당 5분 이상 | 참관 중 "저번에 어떻게 했지" 발화 후 재개까지 시간 | 마커의 가치가 "다시 듣기"보다 "과제 기록"에 있음 → 리뷰 화면 중심 재설계 |

### 대체재 — 사람들은 지금 무엇으로 버티는가

새 앱은 "갈아타는" 것이 아니라 **하나 더 까는** 것이다. 그래서 "왜 하나 더 까는가"에 답해야 한다.

| 대체재 | 지금 맡는 것 | 못 하는 것 | 왜 하나 더 까는가 |
| --- | --- | --- | --- |
| 카카오톡 단톡방 | 일정·잡담·링크·녹음 파일 공유 | 구조 없음. 일주일 지나면 못 찾음 | 안 깐다. 단톡방은 그대로 두고 **결과를 카톡으로 배달**한다(§4.4). 멤버는 앱 설치 없이 링크만 누른다 |
| 네이버 밴드 | 일정·투표·파일·게시판 | 녹음과 시점 연결 없음. 2시간 파일은 여기서도 안 듣는다 | 밴드 앱이 있어도 "어디를 들을지"는 못 준다 |
| 디스코드 | 음성·채팅·파일 | 대학 밴드 일부만 씀. 녹음 시점 연결 없음 | 위와 같음 |
| 아이폰 음성 메모 · 안드로이드 녹음기 | 녹음, 구간 편집 | 편집은 녹음한 사람이 나중에 손으로 해야 함. 아무도 안 한다 | **마커가 자동으로 찍힌다**는 것이 차이. 편집 노동이 0이다 |
| 노션·구글시트 | 셋리스트·곡 목록 | 합주실에서 한 손으로 못 씀. 녹음과 연결 안 됨 | 이걸 이미 잘 쓰는 밴드는 타깃이 아니다(§2) |
| BandHelper · Setlist 계열 앱 | 공연 셋리스트·가사·BPM | 합주 녹음·리뷰 없음. 영어. 공연용 | 합주실 리뷰 축이 없다 |
| BandLab · Soundtrap | 온라인 DAW·협업 녹음 | 합주실 현장 진행과 무관. 과하다 | 과정이 아니라 결과물(트랙) 도구 |
| 합주실 자체 녹음 서비스 | 일부 합주실이 믹서 녹음 제공(유료) | 파일만 준다. 시점 표시 없음 | **앱의 녹음 소스로 오히려 활용**한다(2단계, §9). 경쟁이 아니라 입력 |
| 메트로놈·튜너 앱 | 개인 연습 | 밴드 단위 상태 없음 | 다른 문제 |

## 2. 누가, 어떤 순간에

**1차 타깃**: 정기적으로 **합주실을 돈 내고 빌려** 만나는 3~6인 직장인 아마추어 밴드. 서울 홍대·합정·성수·신촌 합주실 상권 중심.

**타깃 아님** (지금은):
- **대학 동아리 밴드** — 무료 동방에서 합주하므로 "시간이 돈"이라는 압력이 약하고, 세대교체로 밴드 단위 누적이 끊긴다. 2단계 이후 별도 검토.
- **노션·시트로 이미 관리하는 밴드** — 이미 도구가 있고 갈아탈 이유가 약하다.
- 프로 세션, 스튜디오 녹음 팀, 원격 실시간 합주를 원하는 사람(§6).

"아무것도 안 쓰는 밴드가 대다수"는 현재 **가설**이다. 0단계 인터뷰(4팀)에서 "셋리스트를 어디에 적나, 지난 녹음을 어디에 두나"로 확인한다.

| 사용자 | 순간 | 성공의 모습 |
| --- | --- | --- |
| 리더(보통 기타·보컬). 합주를 멈추는 사람 | 합주 시작 전 | 거치대에 폰을 세우고 녹음 시작 버튼 하나. 끝 |
| 리더 | 연주를 멈추고 "브릿지 앞에서 다시" 하는 순간 | **아무것도 안 한다.** 멈춤이 자동으로 마커가 된다. 여유가 있으면 큰 버튼 한 번으로 "이건 중요" 표시 |
| 모든 멤버 | 다음 날 단톡방 | 카톡에 온 카드에서 "3번째 곡 · 다시 4회" 중 하나를 누르면 그 구간 30초가 바로 재생된다. 앱 설치·로그인 없이 |
| 리더 | 다음 합주 이틀 전 | 지난 세션의 마커 중 "안 풀린 것"을 체크해 이번 주 과제로 옮긴다 |
| 공연 준비 밴드 | 공연 2주 전 | 곡별로 최근 3세션 마커 수 추이를 보고 어디에 남은 합주를 쓸지 정한다(MVP 이후) |

## 3. 다른 앱과 뭐가 다른가

"밴드 앱"으로 묶이는 것들은 대개 **연주 자체**(원격 잼, DAW, 튜너)나 **일정**(네이버 밴드)을 다룬다. 합주노트는 **합주실이라는 두 시간의 결과물**을 다룬다.

1. **마커가 자동이다.** 연주가 멈추면 소리가 준다. 그 지점이 마커 후보다. 누가 손을 뗄 필요가 없다. 음성 메모와의 차이는 여기 하나다.
2. **결과가 카톡으로 간다.** 멤버는 앱을 깔지 않는다. 카드 하나, 링크 하나, 구간 재생. 카톡은 경쟁자가 아니라 유통 채널이다.
3. **합주 전·중·후가 이어진다** (MVP 이후). 마커 → 과제 → 다음 셋리스트. 이어주는 도구는 없다.

**모방 방어**: 기능 자체는 베낄 수 있다. 남는 것은 밴드별로 쌓이는 세션·마커·과제 이력이다. 10세션이 쌓인 밴드는 "우리가 뭘 못 맞췄었는지"의 역사를 갖고 있고, 그걸 옮길 곳이 없다. 한계도 분명하다. 이력은 밴드가 해체되면 사라지고, 네이버 밴드 같은 큰 플랫폼이 녹음 마커를 붙이면 유통 채널 우위는 그쪽이 갖는다. 그래서 초기 1~2년은 "합주실 씬에서 먼저 익숙한 이름"이 되는 속도 싸움이고, 합주실 제휴(§9 3단계)가 방어선이다.

## 4. 핵심 기능

### 4.1 MVP-1: 마커 가설만 검증한다

각 기능 옆에 **가설 검증에 필요한가**를 표시한다. N이면 MVP-1에 넣지 않는다.

| 기능 | 내용 | 필요 |
| --- | --- | --- |
| 밴드 만들기 | 이름 하나. 로그인은 호스트(리더)만 카카오 로그인 | Y |
| 세션 녹음 | 호스트 폰 1대. 거치대에 세우고 시작. 화면 켜둠(Wake Lock). 1분 단위 청크로 로컬 저장(중단돼도 최대 1분 손실) | Y |
| 곡 경계 | 녹음 중 "다음 곡" 버튼 한 번 → 곡 경계 타임스탬프. 곡 이름은 나중에 붙여도 됨 | Y — 마커를 곡 단위로 묶어야 카드가 읽힌다 |
| **멈춤 자동 마커** | 녹음 음량(RMS)이 연주 수준에서 대화 수준으로 3초 이상 떨어지는 지점을 "멈춤"으로 감지 → 마커 후보 | Y — 핵심 |
| 손 마커 | 호스트 화면 아래 1/3에 버튼 하나(`중요`). 블루투스 페이지터너 페달(발) 입력도 같은 동작 | Y — 자동 감지 실패 대비 보조 |
| 세션 리뷰 | 곡별 마커 목록. 마커 누르면 멈춤 지점 **N초 전부터** 재생(N 기본 30, 0단계 측정으로 조정). 파일은 자르지 않고 재생 위치만 이동 | Y |
| 마커 정리 | 리뷰에서 마커를 `해결` / `다음에` / `삭제`로 분류. 한 줄 메모 | Y — "다음에" 비율이 가설 지표 |
| **카톡 공유 카드** | 세션 끝나면 "○○밴드 9/6 합주 · 3곡 · 다시 12회" 카드 링크 생성. 링크는 로그인 없이 리뷰 화면(읽기·재생) | Y — 멤버가 실제로 듣는지가 가설 |

### 4.2 MVP 이후 (가설이 살아남으면)

| 기능 | 왜 뒤인가 |
| --- | --- |
| 멤버 로그인·파트 태그, 멤버 폰에서 마커 | 멤버 참여는 0단계에서 "손이 비는가" 확인 후. 호스트 1대로 충분하면 영영 안 만든다 |
| 곡 등록(BPM·키·구조·코드 차트·참고 링크), 곡 상태(제안→연습 중→맞춰봄→공연 가능) | 셋리스트 축. 마커 축이 살아야 의미 있다 |
| 다음 합주 셋리스트 + 곡별 과제 한 줄, "다음에" 마커 자동 승격 | 위와 같음 |
| 시각 메트로놈·카운트인·구조 탭 이동 | 현장 진행 보조. 없어도 마커는 찍힌다 |
| 합주실 믹서 녹음 파일 업로드(호스트 폰 대신) | 2단계 합주실 제휴와 함께 |
| 공연 셋리스트 내보내기, 최근 N세션 마커 추이 | 공연 준비 밴드용 |

### 4.3 안 만드는 것
- 합주실 예약·결제 연동 (합주실별 시스템 제각각)
- 멤버별 개별 트랙 녹음, 믹싱, 악보·타브 편집기
- 실시간 원격 합주 (§6)

## 5. 화면 흐름 (MVP-1)

```
[호스트 홈]  내 밴드 · 최근 세션
   ├ [녹음 ★]   ● 녹음 중 12:34 · 현재 곡 2 · 마커 7
   │             ┌──────────────────────────┐
   │             │  (정보: 시간·곡·마커 수)   │
   │             │                          │
   │             │                          │
   │             ├──────────────────────────┤ ← 아래 1/3
   │             │   [ 중요 ]   [ 다음 곡 ]   │   버튼 높이 72px
   │             └──────────────────────────┘
   └ [세션 리뷰]  곡별 마커 · ▶ 30초 전부터 · 해결/다음에/삭제 · [카톡 공유]

[공유 링크 (멤버, 로그인 없음)]  리뷰 읽기·재생만. 메모는 못 씀
```

현장 규칙:
- **폰 위치**: 마이크 거치대 또는 보면대에 세운다(거치대 필수, 온보딩에서 안내). 주머니는 녹음이 안 되고 앰프 위는 진동이 탄다. 리더 손이 닿는 곳.
- 360px 폭, 세로 고정, 다크. 글자 최소 18px, 주 버튼 높이 72px, 두 버튼만.
- **소리는 내지 않는다**. 알림·피드백은 진동과 화면 플래시.
- 화면 꺼짐 방지(Screen Wake Lock API). 배터리 20% 미만이면 경고 진동.
- 통신은 녹음 중 필요 없다. 업로드는 세션 종료 후, 와이파이 잡히면.

## 6. 왜 실시간 원격 합주를 하지 않는가

- **물리 한계**: 연주자가 어긋남을 못 느끼는 왕복 지연 상한은 대략 20~30ms. 같은 도시 유선에서도 아슬아슬하고, 모바일·와이파이에선 불가능하다. Jamulus·JamKazam이 10년 넘게 매달렸고 여전히 "유선 + 오디오 인터페이스 + 같은 지역"이 전제다.
- **타깃 불일치**: 타깃 밴드는 이미 매주 만난다. 병목은 "함께 연주할 수단"이 아니라 "만났을 때의 결과물"이다.
- **범위**: 1인 개발로 실시간 오디오 네트워킹을 하면 다른 모든 것이 밀린다.

## 7. 기술

### 7.1 스택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 앱 형태 | PWA (React + Vite + TypeScript) | 스토어 심사 없이 배포. 홈 화면 추가. 기존 스택 재사용. 멤버는 링크만 열면 되므로 설치 장벽이 애초에 낮다 |
| 백엔드 | Supabase (Auth · Postgres · Storage) | 1인 개발. Realtime은 MVP-1에서 안 쓴다(호스트 1대라 실시간 전파가 필요 없다) |
| 녹음 | MediaRecorder. **iOS Safari: audio/mp4 (AAC)**, Android Chrome: audio/webm (opus). 모노 64kbps | 플랫폼별 지원 포맷이 다르다. `isTypeSupported`로 분기 |
| 마이크 제약 | `echoCancellation: false`, `autoGainControl: false`, `noiseSuppression: false` | 기본값은 통화용. 드럼·앰프를 뭉갠다. 끌 수 없는 기기는 스파이크에서 확인 |
| 로컬 저장 | 1분 청크를 IndexedDB(idb-keyval)에 즉시 저장 | 브라우저가 죽어도 마지막 1분만 잃는다 |
| 업로드 | Supabase Storage TUS 재개 가능 업로드, 청크 6MB | 지하에서 끊겨도 이어 올린다. 세션 종료 후 와이파이에서 |
| 시킹 | mp4는 문제없음. webm은 길이 메타데이터가 없어 시킹이 깨지므로 청크 병합 시 duration 헤더를 클라이언트에서 보정 | "30초 전부터 재생"의 전제 |
| 멈춤 감지 | 녹음과 병렬로 AnalyserNode RMS를 200ms마다 샘플링, 클라이언트에서 저장. 서버 오디오 처리 없음 | Supabase엔 오디오 컴퓨트가 없다. 서버는 파일과 숫자만 받는다 |
| 공유 카드 | 공개 토큰 링크 + OG 메타(밴드명·날짜·곡 수·마커 수). 카톡 미리보기에 뜬다 | 멤버 설치 0 |
| 이력 보존 | iOS는 7일 미사용 PWA의 로컬 저장소를 지울 수 있다 → 세션 종료 시 업로드를 끝내는 것이 원칙. 업로드 미완료면 홈 화면에 경고 | 주 1회 사용이 7일 경계선 위 |

### 7.2 기술 스파이크 (0단계, 1주) — 통과 못 하면 MVP 시작 안 함

실제 합주실에서, 실제 밴드 합주 중에 돌린다.

| 확인 항목 | 통과 기준 |
| --- | --- |
| iOS Safari(최신 2개 버전) + Android Chrome에서 2시간 연속 녹음 | 끊김 0회. 카톡 알림·전화 수신 시 동작을 기록(끊기면 "방해금지 모드 안내"로 대응 가능한지 판단) |
| 마이크 제약 해제 | 드럼·앰프 구간 클리핑 없음, AGC로 인한 펌핑 없음(파형 육안 + 청취) |
| 파일 크기·업로드 | 2시간 ≤ 70MB. 지하에서 시작한 업로드가 지상에서 이어져 완료 |
| 시킹 정확도 | 마커 지점으로 이동 시 오차 ±1초 이내 |
| 멈춤 자동 감지 | 참관 기록과 대조해 실제 멈춤의 80% 이상 감지, 오탐(곡 중 브레이크·조용한 인트로)은 마커 후보의 50% 이하 |
| 배터리 | 화면 켜둔 채 2시간 녹음 후 잔량 30% 이상(시작 100%) |

한 항목이라도 실패하면: 녹음 소스를 호스트 폰이 아니라 **합주실 믹서 녹음 파일 업로드**로 바꾸고(멈춤 감지는 업로드 후 클라이언트에서 분석), 그것도 안 되면 프로젝트를 접는다.

### 7.3 Capacitor 대안의 비용
iOS PWA 녹음이 스파이크를 통과 못 하면 Capacitor 네이티브 래퍼가 대안이다. 그 비용을 미리 적는다: 애플 개발자 계정 연 99달러, 심사 1~2주, 업데이트마다 심사, "스토어 심사 없이 배포"라는 PWA 선택 이유가 사라짐. 호스트(리더)만 설치하면 되므로 감당 가능한 범위지만 로드맵에 3주를 추가한다.

## 8. 수익과 비용

### 8.1 누가 왜 내는가
밴드 단위 결제. 리더 한 명이 결제하고 멤버 전원이 혜택. 합주실비를 이미 회비로 걷고 있어 개인 결제보다 저항이 적다는 것이 가설이다.

| 플랜 | 내용 |
| --- | --- |
| 무료 | 밴드 1개, 녹음 보관 **14일**, 세션 이력 무제한(마커·메모는 남음) |
| 밴드 프로 (월 4,900원 가설) | 녹음 보관 **1년 또는 10GB**, 공유 카드 만료 없음, 곡·셋리스트 축(MVP 이후) |

"보관 무제한"은 비용 상한이 없으므로 넣지 않는다.

### 8.2 숫자의 출처

| 숫자 | 현재 상태 | 채우는 방법 |
| --- | --- | --- |
| 월 4,900원 | 가설. 합주실 2시간 비용(4~6만 원)의 10% 이하로 잡음 | 0단계 인터뷰 문항: "밴드 회비 월 얼마, 도구에 월 얼마까지" |
| 서울 정기 합주 밴드 수 | **미측정**. 방법만 정함 | 네이버 지도 "합주실" 서울 4개 상권 검색 결과 수 × 합주실당 방 수 × 주말 슬롯 × 정기 밴드 비율(합주실 사장 인터뷰). 0단계에서 계산 |
| 유료 전환율 10% | 가설. 소규모 그룹 SaaS 무료→유료 전환 일반 범위(2~5%)보다 높게 잡은 것이므로 **낙관적** | 2단계에서 측정. 아래 손익분기는 5%로도 계산 |

### 8.3 비용과 손익분기

밴드당 월 녹음량: 4세션 × 2시간 × 64kbps ≈ **230MB**. 재생(이그레스)은 마커 구간만 들으므로 녹음량의 20%로 가정.

| 항목 | 단가 | 근거 |
| --- | --- | --- |
| Supabase Pro | 월 25달러 (100GB 저장·250GB 이그레스 포함) | 공개 요금표 |
| 추가 저장 | GB당 월 0.021달러 | 공개 요금표 |
| 추가 이그레스 | GB당 0.09달러 | 공개 요금표 |

| 시나리오 | 저장량 | 월 비용 | 월 매출 | 결과 |
| --- | --- | --- | --- | --- |
| 무료 180팀 + 유료 20팀 (전환 10%) | 무료 14일 보관 ≈ 180×115MB = 21GB, 유료 누적 1년 ≈ 20×2.8GB = 56GB → 77GB | 25달러 (포함 범위 내) ≈ 3.4만 원 | 20 × 4,900 = 9.8만 원 | 흑자 |
| 무료 190팀 + 유료 10팀 (전환 5%) | 22GB + 28GB = 50GB | 3.4만 원 | 4.9만 원 | 흑자 |
| 무료 1,000팀 + 유료 50팀 (5%) | 115GB + 140GB = 255GB → 초과 155GB | 25 + 3.3 ≈ 28달러 ≈ 3.9만 원 (이그레스 ≈ 48GB, 포함 범위 내) | 24.5만 원 | 흑자 |

결론: 서버비는 유료 밴드 10팀이면 넘는다. **인건비는 0으로 계산했다.** 이 프로젝트는 1~2년 안에 생활비를 내는 사업이 아니라, 1인이 서버비를 잃지 않으면서 합주실 씬에 자리를 잡는 것이 목표다. 주간 활성 밴드 200팀이 12개월 내 안 나오면 유료화 자체를 접고 무료 도구로 남길지 판단한다(§9 3단계 실패 기준).

## 9. 로드맵

주당 개발 투입: **12시간** (평일 저녁 2시간 × 3 + 주말 6시간). 8주 = 약 100시간.

| 단계 | 기간 | 내용 | 통과 기준 | 실패 기준 → 행동 |
| --- | --- | --- | --- | --- |
| 0-a. 참관·인터뷰 | 2주 | 내 밴드 + 지인 밴드 3팀, 합주 각 1회 참관 + 리더·멤버 인터뷰 | §1 가설 3개 측정. 멈춤 세션당 10회 이상이 4팀 중 3팀 | 4팀 중 2팀 이하 → 마커 축 폐기, 셋리스트·과제 축으로 피벗 |
| 0-b. 기술 스파이크 | 1주 (0-a와 병행) | §7.2 전 항목, 실제 합주실에서 | §7.2 통과 기준 전부 | 실패 → 믹서 파일 업로드로 소스 변경. 그것도 안 되면 중단 |
| 1. MVP-1 | 8주 | 아래 주 단위 계획 | 내 밴드 + 지인 1팀에서 4주 연속 세션. **세션 후 72시간 내 공유 카드 열람 멤버 비율 50% 이상, 마커 재생 비율 30% 이상** | 열람 50% 미만 → 카드 문구·미리보기 재설계 후 2주 재측정. 재생 30% 미만 → "다시 듣기" 가치 없음, 마커를 텍스트 과제 기록으로 전환 |
| 2. 베타 | 6주 | 지인 밴드 5팀 → 홍대·성수 합주실 게시판·밴드 커뮤니티 모집 10팀 | 15팀 중 **8팀 이상**이 3주 연속 사용. 리더 외 멤버 카드 열람 50% 유지 | 8팀 미만 → 공개 보류, 이탈 밴드 인터뷰 후 재설계 |
| 3. 공개 | 12주 | 유료 플랜 오픈. 합주실 제휴(방에 QR → 밴드 생성). 믹서 녹음 연동 | 12개월 시점 주간 활성 200팀, 유료 전환 5% 이상 | 미달 → 유료화 접고 무료 도구로 유지할지, 중단할지 결정 |

**1단계 주 단위 계획**

| 주 | 작업 |
| --- | --- |
| 1 | 프로젝트 셋업, 카카오 로그인, 밴드 생성. 녹음 화면 껍데기 |
| 2 | 녹음: 포맷 분기, 마이크 제약, 1분 청크 IndexedDB 저장, Wake Lock |
| 3 | 멈춤 감지(RMS), 손 마커, 페달 키 입력, 곡 경계 버튼 |
| 4 | 세션 종료 → 청크 병합(duration 보정) → TUS 업로드 → 재개 |
| 5 | 세션 리뷰: 곡별 마커, N초 전 재생, 해결/다음에/삭제, 메모 |
| 6 | 공유 카드: 공개 토큰, OG 메타, 로그인 없는 리뷰 읽기 화면 |
| 7 | 내 밴드 실사용 1주차. 버그·현장 문제 수정 |
| 8 | 지인 1팀 투입. 열람·재생 지표 수집 시작(단순 이벤트 로그) |

지표는 Supabase 테이블에 이벤트(카드 열람·마커 재생) 한 줄씩 기록하는 수준으로 시작한다. 분석 도구는 넣지 않는다.

## 10. 리스크와 반론

| 반론 | 판단 | 대응 |
| --- | --- | --- |
| **합주 중 마커 누를 손이 없다** | 맞다. 기타·베이스는 두 손, 드럼은 스틱, 보컬은 마이크 | 그래서 자동 감지가 기본이고 손 마커는 보조다. 멤버 폰 마커는 MVP에서 뺐다. 0단계에서 "멈춘 뒤 리더가 폰을 누를 여유가 있는가"를 세션당 횟수로 관찰하고, 60% 미만이면 손 마커도 페달 전용으로 바꾼다 |
| **멤버는 앱을 안 연다. 리더가 캡처해서 카톡에 올린다** | 맞다. 그래서 캡처 대신 카드다 | 카톡 안에서 미리보기가 뜨고, 링크 하나로 로그인 없이 30초 구간이 재생된다. 열람·재생 비율이 1단계 통과 기준이다. 이게 안 되면 앱은 리더 개인 도구이고, 밴드 단위 결제 명분이 없다 → 실패 기준에 반영 |
| **녹음 파이프라인이 안 돌아간다** (iOS 2시간, AGC, 업로드, 시킹) | 가장 위험한 기술 가정 | 코드 전에 §7.2 스파이크 1주. 실패 시 믹서 파일 업로드로 소스 변경 |
| **호스트 폰 한 대가 단일 장애점** | 맞다 | 1분 청크 로컬 저장으로 손실 최대 1분. 밴드 내 누구든 호스트가 될 수 있게(로그인만 하면) 2단계에서 열고, 믹서 녹음 연동을 대안 소스로 |
| **자동 감지가 오탐·미탐한다** (곡 중 브레이크, 조용한 인트로, 멈추고 바로 다시 침) | 있을 것이다 | 마커는 "후보"이고 리뷰에서 삭제 한 번이다. 오탐 50% 이하가 스파이크 통과 기준. 손 마커·페달이 미탐을 보완 |
| **돈이 안 된다** | 10% 전환은 낙관적 | 5%로도 서버비는 넘는다(§8.3). 인건비는 애초에 계산에 없다. 12개월 200팀 미달 시 유료화를 접는다는 기준을 미리 둔다 |
| **네이버 밴드가 같은 걸 붙이면** | 유통 우위는 그쪽 | 초기 1~2년 합주실 씬 인지도 + 합주실 제휴(QR·믹서 연동)가 방어선. 그래도 지면 진다. 그 전에 밴드별 이력이 쌓여 있는 것이 유일한 자산 |
| **iOS PWA 녹음 제약** | 스파이크에서 판정 | 통과 못 하면 Capacitor. 비용은 §7.3에 적어 뒀다 |
| **합주실 통신 불량** | 지하가 많다 | 녹음 중 통신 불필요. 업로드는 사후·재개 가능 |
| **1인 개발 범위 초과** | 늘 그렇다 | MVP-1은 §4.1 8개 기능, 100시간. 나머지는 가설이 살아남은 뒤에만 |
