## ⚠ 지금 막혀 있는 것 — 폰트

`public/fonts/*.woff2` 가 **비어 있다.** 그래서 지금 앱은 시스템 폰트로 그린다.

이게 왜 중요한가: 폰트가 대체 폰트로 떨어지면 **줄바꿈이 달라지고 측정이 어긋나** 조판이 통째로 틀어진다. «인쇄하면 화면 그대로»가 깨진 줄도 모른 채 깨진다. 그래서 `fontGuard.ts` 가 개발 빌드에서 크게 경고하고, 조판 엔진은 `fontsReady` 가 참일 때만 지면을 그린다.

채우려면 둘이 필요하다.

1. **원본 폰트** — Noto Serif KR / Noto Sans KR 의 `.otf` 를 `assets/fonts-src/` 에.
   CDN 금지(PP§6.4)이므로 빌드 시점에 파일로 갖고 있어야 한다.
2. **서브셋 도구** — `pip install "fonttools[woff]" brotli`

그다음 `npm run fonts:subset` 이 KS X 1001 한글 2,350자 + 한자 4,888자로 줄이고 **실제 용량을 출력한다.** 그 숫자가 «서브셋이 예산에 드는가»(zz-0 D7)의 답이다.

> 글자 목록은 코드에 박혀 있지 않다. EUC-KR 바이트를 디코드해 얻는다 — 표를 손으로 옮기면 반드시 틀린다.

## 구조

```
src/
  app/        셸·스토어·단축키·등급·폰트 — 나머지 전부의 토대
  components/ 공용 인벤토리 (SS부록A) — 화면마다 새로 만들지 않는다
  domain/     데이터 모델 (PP§6.2)
  layout/     조판 엔진 — **순수 함수만.** DOM·React 를 import 하지 않는다 (zz-2)
  print/      인쇄 코어 (zz-2 소유)
  screens/    화면별 구현
  styles/     tokens.css 가 색·서체·간격의 단일 출처
```

## 스타일을 어디에 쓰는가 — Tailwind 와 인라인의 경계

Tailwind 를 쓰되(PP§9.1), **토큰에서 값이 나오는 것은 인라인 스타일로 쓴다.**

| 무엇 | 어디 | 왜 |
| --- | --- | --- |
| 골격 치수·색·간격 | 인라인 `style` + `var(--…)` | 값의 출처가 `tokens.css` 하나여야 한다. Tailwind 로 쓰려면 같은 값을 `tailwind.config.ts` 에 한 벌 더 적게 되고, **두 곳에 둔 값은 반드시 갈라진다** |
| 지면·인쇄 | `print.css` (순수 CSS) | 인쇄 CSS 는 유틸리티로 표현할 것이 아니다 (PP§9.1) |
| 그 밖의 배치·여백 | Tailwind 유틸리티 | 토큰과 무관한 일회성 배치 |

`npm run check:ds` 가 토큰이 디자인 시스템 원본과 같은지 대조한다.

## 이 코드베이스의 규칙 넷

1. **하드코딩 hex 금지.** 색은 `tokens.css` 의 CSS 변수만. 24px 미만 텍스트에
   `--color-accent` 금지 — 배경 대비 3.0:1 로 AA 미달이다 (`contrast.test.ts` 가 근거)
2. **사용자에게 보이는 한글은 `strings.ts` 에만.** 개발자용 진단은 영어로 둔다
3. **`layout/` 은 순수 함수.** 측정은 바깥에서 주입한다
4. **외부 요청 0건.** 학교 망은 외부를 막는 경우가 있다 (`no-cdn.test.ts` 가 지킨다)
